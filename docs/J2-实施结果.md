## 6. ★ 判据维护：这一阶段学到的三件事

`J2` 是**第一个真正改动 `src/cabin/**` 的阶段**（`J1.5` 的 DoD 是"一行未改"），
于是三条为搬迁前设计的安全网同时到了适用边界。处理方式**不是放宽**，而是三种不同的正解：

| 情形 | 例子 | 处理 |
|---|---|---|
| **历史链条必然断裂** | `verify-f06` 的「撤销 J0.6 → 与 F0.4 快照一致」 | **降级为参考项**并写明理由（该事实在 `J0.6` 收尾时已验过；`J4` 删除 monolith 后脚本退役） |
| **判据的适用范围变了** | `verify-migration` 的关键标识符计数（几何/材质/随机调用被搬进模块） | **扩大扫描范围**：从「monolith + dom.js」→「`legacy/core/systems/world/props` + `dom.js`」，排除 `app/**` 与 `boot.js`（那是 F0.2/J1 新增的基础设施）。**强度不降**：搬运不改变总数 |
| **基线语义变了** | `cabin-digest.json`（"J1.5 一行未改"） | **重录 + 改语义**：转为"3D 源码指纹"，节奏定为**每个任务收尾前重录**（任务内变红属预期） |

> 一条具体经验（`J2.7` 踩到）：`verify-migration` 按**名字**追踪那 286 处随机调用的去向。
> 搬进模块时形参名要保持可识别（`runtimeRng`），且**注释里不能出现带括号的裸随机字样**
> —— 否则计数会少 3（改名）或多 2（注释）。`J3`/`J4` 搬 286 处随机调用时请记住这条。

## 7. 关键设计决定（跨任务）

| 决定 | 原因 |
|---|---|
| **解构保留原标识符名** | monolith 内 2000+ 处调用点零改动，搬迁的爆炸半径收敛为"文件头 + 定义处" |
| **依赖注入而非 import 全局** | `core/` 不持有 `scene`、不出现具体物件名（`N1`/`N7`）；`solidCyl` 的默认材质（原来是猫的 `CATMAT`）也改为注入 |
| **工厂而非模块级单例** | 集合的生命周期与"一局"绑定；避免新增全局可变状态（`N7`） |
| **shader 与 uniforms 用脚本逐字节提取** | 手抄一个空格或小数就会改变画面，而像素回归只会说"不一样" |
| **注册顺序 = 优先级 / 槽位顺序** | `aimTarget()` 的短路顺序就是行为；shader 的闪烁相位含 `float(i)`，槽位一变画面就变 |
| **测试环境必须与存储无关** | `?deterministic=1` 下 `persist: false` —— 否则"上次测试改了视角"会伪装成画面差异 |
| **脚本化改写 + 自检** | 15 处散落常量、135 行 shader、三块材质定义：手改易漏，脚本能在**写盘前**拦下（`_j29` 的自检就拦下过一次误判） |

## 8. 明确的偏差留痕（三处）

| 项 | 路线图怎么写的 | 实际怎么做 | 为什么 / 何时补 |
|---|---|---|---|
| `J2.2` | 「炉火/吊灯/点光**三段重复逻辑合一**」 | **只做参数化，未做 GLSL 内部重构** | 原则 2「搬迁期零优化」+ 像素逐字节零差异的判据不允许改 shader 结构；真正需要它的是 `J2.3`（数据驱动，已做）与 `J8`（调优）。落点已收敛到 `fill.frag.glsl.js` 一个文件 |
| `J2.6` | 「64 处 `regMagic` + 9 条 `interactables` + **镜子自建射线** → 一个契约」 | **主路径（三套）已统一；镜子未迁移** | 镜子不看遮挡、且需要"命中点的局部坐标"，迁进来是**行为变化**。`types.js` 已补 `localPointOf()`，留给 `J3` 随物件搬迁一起做 |
| `J2.6` | 「`label` 必须语义化」 | **契约已强制，但 64 处旧物件缺省仍落到 `'交互'`** | 逐条补文案随 `J3` 的物件搬迁做（`J3` 的 DoD 明确写着"`label` 有语义"） |

## 10. 环境与流程备注（本机）

| 项 | 说明 |
|---|---|
| **端口** | 默认 5173 落在 **Windows 保留端口段 5119–5218**，绑定必然 `EACCES` ⇒ 本阶段一律用 `--port=4173` + `CABIN_URL` |
| **pnpm** | `pnpm <script>` 会触发依赖自检并要求 TTY（`ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`）⇒ 一律用 `node <入口>` 直接调用等价脚本 |
| **构建** | `astro build` 需要 esbuild 子进程（命名管道）⇒ 在受限沙箱下会 `spawn EPERM`；`serve` 需能监听端口 |
| **浏览器测试** | headless Chrome 需要命名管道（mojo）⇒ 受限沙箱下必然 `Check failed: 拒绝访问 0x5` 自终止 |
| **`astro` 入口** | 不在 `node_modules/astro/astro.js`，而是 `node_modules/astro/bin/astro.mjs` |
| **`node --test`** | 目录形式（`node --test tests/unit/`）在 Node 24 上会被当成模块入口而 `MODULE_NOT_FOUND` ⇒ 必须用 glob 形式 |
| **工具修复（3 处）** | `release.mjs`：① git 正常提示走 stderr 被误判失败；② 降级路径丢失参数引号（`merge -m` 消息被拆散）；③ 新增 `done --base=x.y.z`（`Jx.y` 在本项目里既可能是阶段内任务也可能是独立子阶段） |
