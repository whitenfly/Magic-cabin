# 04 · 模块增量开发与配置编排（决策 4 + 决策 5）

> **决策 4**：后续其他功能模块采用**增量开发**，一个功能模块一个功能模块地来；
> **最终由作者决定每个功能模块映射到什么模型上、如何交互和展示**；
> 路线中只留**建议映射方案**，映射方案**单独留文件**（[`mapping.yaml`](./mapping.yaml)），便于修改与模型读取。
>
> **决策 5**：各个功能模块的配置**参考 Firefly 的编排方法**，需要**用户友好**且**将设置集中在一起**，便于修改。
>
> **本文档给出两样东西**：§2 的**模块九步 SOP**（决策 4 的执行形式）与 §3 的**配置编排方法**（决策 5 的落地方案）。

---

## 1. 两个决策的共同前提：模块是"目录"，不是"一行注册"

`ArtLine-Part/02` §3.1 把"加功能"设计成"**加一个文件 + 加一行**"（`src/features/index.ts` 里加一行）。
决策 4 把粒度**再提高一级**：

| | 上游设计 | **本路线** |
|---|---|---|
| 增量单元 | 一个 `Feature` 对象 | **一个 `src/features/<NN>-<id>/` 目录** |
| 加一个模块 | 写代码 + 在 `index.ts` 加一行 | 建目录（内含自己的配置引用、纯函数模型、数据适配、面板、场景挂载）+ 在 `_index.js` 加一行 |
| 停一个模块 | 删那一行（代码留着） | **改 `modules.config.js` 一个布尔值**（代码留着，且**不被打包/不加载**） |
| 谁决定映射 | 开发者 | ★ **作者**——改 [`mapping.yaml`](./mapping.yaml) |

**为什么粒度要提到"目录"**：因为一个模块实际上有 **5 个面**（配置 / 数据 / 纯函数模型 / 场景挂载 / 面板），
散在 5 个地方就无法"一个一个地来"。目录把它们绑在一起。

## 2. 模块九步 SOP

> **适用**：`J7` 阶段每加一个模块；也适用于把已完成的 M01 回填成规范形态。
> **原则**：**每一步都可停下来**——任何一步结束时项目都处于可运行、可部署状态。

### S0 · 选模块（5 分钟）

从 [`mapping.yaml`](./mapping.yaml) 里挑一个 `status: proposed` 的模块。
**先看 `depends` 字段**：依赖未就绪的模块不要提前开。

### S1 · 作者拍板（★ 唯一需要人工决策的一步）

只看 `mapping.yaml` 该模块的这几个字段，逐项确认或改写：

| 字段 | 含义 | 例 |
|---|---|---|
| `item` | 承载物品（可以是一件或"主+控制器"两件） | 一楼左墙三层书架 + 左窗下书堆 |
| `itemRef` | 该物品在源码中的位置（便于定位） | `L1937–1970`（迁移后为 `cabin/world/floor1/bookshelf.js`） |
| `mount` | 挂载点 ID（在 `cabin/app/mounts.js` 里注册） | `shelf/main` |
| `render.channels` | **呈现通道**（四通道，可多选） | `[B, D]` |
| `render.detail` | 通道细节（页面尺寸 / 贴图规格 / DOM 层形态） | 书页 2 栏，平面视角 |
| `interaction.mode` | `aim` / `proximity` / `both`（**必须 `both`**，见 `BB2b`） | `both` |
| `interaction.activate` | 激活后的动作序列 | 抽书 → 翻开 → 进入阅读 |
| `commands` | 该模块注册/调用的命令名 | `shelf:open`、`post:open` |
| `configKeys` | 该模块用到的配置键 | `shelf.*`、`reader.*` |
| `accept` | 该模块的验收项 | `BB4`、`BB6`、`CH1`–`CH3` |

**改完把 `status` 改为 `confirmed`。** 这是"拍板"的动作，之后实现与模型都以它为准。

### S2 · 写配置（0.1–0.2 人日）

1. 新建 `src/config/<module>.config.js`（**一模块一文件**）；
2. 在 `src/config/index.js` 加一行 re-export（含类型）；
3. 在 `src/config/types.js` 加该配置的 `@typedef`；
4. 在 `src/config/modules.config.js` 的开关表里把该模块置 `true`；
5. 在 `src/config/README.md` 的清单表里加一行。

> 规则细节见 §3。**这一步的产出物全部是"用户可见的旋钮"。**

### S3 · 写纯函数模型 `features/<NN>-<id>/model.js`（0.1–0.3 人日）

**输入**：数据（`posts.json` / 集合 / 本地 JSON / 统计对象）
**输出**：呈现参数（颜色、尺寸、位置、角度、亮度、液面高度……）

**硬要求**：

- **零 3D 依赖**（不 import three，不碰 DOM）→ 可单测；
- **零副作用**（纯函数）；
- 每个输出参数都能在配置里找到对应的可调项或明确的推导公式。

```js
// features/04-taxonomy/model.js
/** @param {PostMeta[]} posts @returns {ReagentDisplay[]} */
export function reagentDisplay(posts, cfg) {
  // 7 个瓶子：按文章数降序取前 7 个标签
  // 液面高度 = clamp(0.25 + ratio * 0.75, 0.25, 1.0)   ← 公式写在这里，常数来自 cfg
}
```

### S4 · 写数据适配 `features/<NN>-<id>/data.js`（0.1 人日）

只做**读取**，不做写入（状态所有权：见 `Blog-Part/03` §6.1 的所有权表）。

| 数据来源 | 怎么读 |
|---|---|
| 文章元数据 | `blog/ContentLoader.posts()`（内存缓存，零网络） |
| 统计信息 | 构建期算好，随 `posts.json` 一起产出 |
| 本地 JSON（友链/书签/歌单） | `src/data-local/*.json`（Astro 构建期可内联或产出为静态文件） |
| 第三方 API（ACG 收藏等） | **构建期抓取**（对齐 `R10`：走 `static` 模式，失败时构建告警，运行时表现为"那个环不亮"） |

### S5 · 场景挂载 `features/<NN>-<id>/scene.js`（0.2–0.4 人日）

```js
// features/04-taxonomy/scene.js
export function mount(ctx) {
  const rack = ctx.mounts.get('reagent/rack')          // ← 挂载点对象（N3：不 import world 实现）
  for (const [i, r] of rack.bottles.entries()) {
    ctx.interaction.add({
      id: `taxonomy/${i}`,
      label: () => `${r.name} · ${r.count} 篇`,
      mode: 'both',                                     // ★ 必须 both（BB2b）
      object3D: rack.bottles[i].mesh,
      anchor: rack.anchor, radius: 1.8,
      floatingCard: () => ({ title: r.name, meta: [{ text: `${r.count} 篇文章` }], accent: r.color }),
      onActivate: () => ctx.commands.run('shelf:focus', { tag: r.name }),
    })
  }
  rack.onUpdate((dt, time) => { /* 液面高度、晃动 */ })
}
```

**三条硬要求**：

1. `mode: 'both'`——**每个模块的主入口必须在三种视角下都能激活**（`BB2b`，风险 `R1`）；
2. `label` **必须语义化**——不得出现字面量"交互"（`BB2`）；引导性文案优先（"看看有哪些主题"）；
3. 坐标/锚点**必须来自 `cabin/app/mounts.js`**，不得手抄字面量（不变量 `N9`）。

### S6 · 写面板 `features/<NN>-<id>/panel.*`（0.2–0.5 人日）

**按 `mapping.yaml` 的 `render.channels` 选形态**（判据见 [`03`](./03-渲染通道与构建选型.md) §4.2）：

| 通道 | 面板形态 | 文件 |
|---|---|---|
| **B** | **不需要独立面板**——内容直接渲染进 CSS3D 书页 | `blog/reader/*` + 该模块的 `content.js`（提供 DOM 节点） |
| **A** | Canvas 绘制函数（画到贴图） | `panel.canvas.js` |
| **T4** | **不需要面板**——只写 `model.js` 的输出到物件属性 | — |
| **D** | DOM 覆盖层（2D）；有状态者用**原生 ESM 动态 import**（⚠️ 不要写成 Astro 岛，见 `03` §5.4） | `panel.dom.js` + `panel.css` |

**视觉同源是硬要求**（`BB12`）：羊皮纸底 `#faf4e4`、烫金 `#b8912a`、衬线字体、纸张噪点——
色值取自场景已有的 `drawClock` / `drawRug` / `drawBoardFace`。

### S7 · 注册命令 `features/<NN>-<id>/commands.js`（0.1 人日）

- 该模块**对外提供**的命令名（供场景物品调用）；
- 该模块**调用**的命令名（应已存在于 `blog/commands.js`；若需新增，先在 `blog/commands.js` 里加声明）。

命名规范：`<域>:<动作>`，例：`shelf:open`、`search:open`、`music:toggle`、`gallery:unlock`。
完整命名表见 [`Blog-Part/03`](../../../docs/Blog-Part/03-映射契约与交互规范.md) §5.1（**沿用，不另起一套**）。

### S8 · 验收（0.2–0.3 人日）

逐条跑 `mapping.yaml` 里该模块的 `accept` 列表 + 下面这张通用清单：

| 检查 | 判定 |
|---|---|
| 三视角可达（`fixed`/`tp`/`fp`） | 3 次手测，均能激活主入口（`BB2b`） |
| `label` 语义化 | 断言 != "交互"（`BB2`） |
| 关闭该模块（`modules.config.js` 置 false） | 场景无报错、物品恢复纯装饰、点击给"这件东西还没启用"浮签（`BB3`） |
| 新增一篇 `.md` | 该模块数据自动更新，**零代码改动**（`BB4`） |
| 无 Firefly import | 静态 import 图检查（`BB5`） |
| 数据真源唯一（多通道时） | 评审 + 运行时统计（`CH6`） |
| 配置项全部来自 `src/config/` | 评审：代码里不得出现该模块的可调常数 |
| 像素回归 | 与 `J0.4` 基线比对（只允许该模块影响的机位有差异） |

### S9 · 回填（5 分钟）

1. `mapping.yaml` 的 `status` 改为 `shipped`；
2. `impl` 字段填实际落地位置（`features/<NN>-<id>/`）；
3. `notes` 写偏差与原因（**不要偷偷改实现**）；
4. `01-完善路线图.md` §2 的状态列不需要改（模块进度只看 `mapping.yaml`）。

## 3. 配置编排方法（决策 5）

### 3.1 Firefly 的九条方法（实测自 `src/config/`，28 个文件）

| # | 方法 | Firefly 的实证 |
|---|---|---|
| **F1** | **一模块一文件** | `musicConfig.ts` / `galleryConfig.ts` / `commentConfig.ts` … 共 28 个；每个文件只 `export const` 一个对象 |
| **F2** | **类型分离** | `src/types/<x>Config.ts` 声明 interface；配置是数据，类型可被实现与校验共用 |
| **F3** | **索引汇总** | `src/config/index.ts` 统一 re-export（**含类型导出**），组件一次导入多个相关配置 |
| **F4** | **README 是用户第一站** | `src/config/README.md` 列出每个文件"干什么"，并写明推荐导入方式 |
| **F5** | **分区注释 + 逐字段注释** | 文件内 `// ── 外观 (Appearance) ──` 分节；**每个字段上方一行中文注释说清"改了会怎样"**（例：`displaySettingsConfig.enable` 上方直接写"开启后大概 +33 KB/页"） |
| **F6** | **默认 + 运行时覆盖** | `resolve*()` 工具（`resolveDisplaySettingsConfig` / `resolvePageToggles` / `resolveSiteLang`）读环境变量；**环境变量优先级高于文件**，未设置或无法识别时用文件值 |
| **F7** | **页面/功能总开关** | `siteConfig.pages.<x> = false` → 页面返回 404 **并自动隐藏对应导航项**（"关一个功能"是一行配置） |
| **F8** | **配置影响构建体积** | 设置面板总开关关闭 → 相关客户端 JS **不进产物**（注释里量化了体积差）。**配置不只是行为开关，也是构建裁剪开关** |
| **F9** | **配置 = 默认值，面板 = 运行时覆盖** | `displaySettingsConfig` 决定哪些项**对用户可见**；面板改动存 `localStorage` |

> **这九条里，真正的精髓是 F1 + F4 + F7 + F9 四条**：
> 用户在**一个目录**里改、**一个开关**关掉一个功能、**一处注释**知道后果、**一个面板**在运行时试。

### 3.2 小屋的配置目录

```
src/config/
├─ README.md              ★ 用户第一站（对齐 F4）
├─ index.js               统一导出（含类型导出）        ← F3
├─ types.js               每个配置的 @typedef 形状声明   ← F2（JS 项目用 JSDoc）
├─ resolve.js             resolve*() 环境变量覆盖工具    ← F6
│
├─ site.config.js         站点：标题/副标题/作者/URL/语言/导航/页脚/SEO 默认值
├─ cabin.config.js        3D：默认视角/画质档/天气/时间流速/启动策略/门厅行为
├─ modules.config.js      ★★ 模块总开关表                ← F7 的落点
├─ shelf.config.js        书架：层规格/排序/分组/厚度公式/溢出策略/策展视图
├─ reader.config.js       阅读器：通道 B 页面尺寸/字号/平面视角/长文阈值/移动端
└─ <module>.config.js     每个功能模块一个（M02…M18），随 S2 创建
```

**四条目录规则**：

1. **集中**：任何面向用户的旋钮都在 `src/config/`，**不得**散落到 `features/**` 或 `cabin/**`（对应不变量 `N11`）；
2. **叶子**：`config/` 不得 import `cabin/**`、`blog/**`、`features/**`（配置不能读实现）；
3. **一对一**：一个已上线模块对应**恰好一个**配置文件；没配置的模块说明它还没到 `confirmed`；
4. **可缺省**：删掉某个模块的配置文件必须导致**构建失败**（而不是静默用默认值）——防漂移（对应风险 `R30`）。

### 3.3 `modules.config.js`：一行关掉一个模块（F7 的落点）

```js
// src/config/modules.config.js
// 模块总开关：false = 该模块完全不启用
//   ① 场景侧：它的 interactable 不注册，物品恢复纯装饰（点击给出「这件东西还没启用」）
//   ② 站点侧：它的页面/面板不生成（对齐 Firefly 的 siteConfig.pages.* = 404 + 隐藏导航项）
//   ③ 加载侧：它的 features/<id>/ 代码不被 import（见 §3.4）
// 改完刷新即可，无需改任何其他文件。
import { resolveModules } from './resolve.js'

export const modulesConfig = resolveModules({
  // ── 内容骨架（不可关，关掉站点就没有内容）──────
  M01: true,   // 内容存档 → 书架 + 阅读器

  // ── 内容发现 ────────────────────────────────
  M02: true,   // 时间归档 → 大地毯（年历）+ 台历
  M03a: true,  // 搜索     → 水晶球占卜台
  M03b: true,  // 随机一篇 → 扑克牌堆
  M04: true,   // 主题聚类 → 试剂药水架

  // ── 社交面 ──────────────────────────────────
  M07: true,   // 名片与导航 → 魔女帽 + 月光盆栽
  M08: true,   // 评论互动   → 抽纸盒 + 计划板便签
  M10: true,   // 照片相册   → 前墙相框组 + 雪景球

  // ── 氛围与个性化 ────────────────────────────
  M11: true,   // 音频播放 → 暖桌上的收音机
  M13: true,   // 站点统计 → 烟囱墙魔法时钟

  // ── 不映射到场景 ────────────────────────────

```

### 3.4 三种"关掉"的语义（对齐 F7 + F8）

| 层面 | 关闭后发生什么 | 实现 |
|---|---|---|
| **场景侧** | 该模块的 `interactable` 不注册；物品恢复纯装饰；点击给出「这件东西还没启用」浮签 | `blog/registry.js` 按 `modulesConfig` 过滤后再 `mount(ctx)` |
| **站点侧** | 该模块的独立页面/面板不生成（构建产物里没有） | Astro 页面在 `getStaticPaths()` 里读 `modulesConfig`；导航项由配置驱动的单一函数生成 |
| **加载侧** | 该模块的 `features/<id>/**` **不被 import、不被下载** | ① 3D 侧：`import.meta.glob('./features/*/index.js')` + 按配置过滤（未启用者**不触发动态 import**，其 chunk 不会被请求）；② 站点侧：Astro 组件层面天然按配置裁剪 |

> ⚠️ **诚实说明**：`import.meta.glob` 的分支是**加载期裁剪**（不下载），不是**构建期 tree-shake**（不产出 chunk）。
> 对"用户感知"（关闭的模块不加载、不注册、不报错）**完全达标**；
> 若作者要求产物里也彻底没有这些 chunk，`J8` 可加一个 `scripts/gen-features-index.mjs`（读配置生成 `_index.js` 的静态 import 清单）。
> **不建议现在做**——它会让"改一个布尔值"变成"改一个布尔值 + 跑一次 codegen"，违背决策 5 的"便于修改"。

### 3.5 运行时设置面板（F9 的落点）

```js
// src/config/display.config.js（M17 显示设定 的配置）
export const displayConfig = {
  // 总开关：关闭则设置面板不渲染，相关客户端代码不进产物（对齐 Firefly 的 displaySettingsConfig.enable）
  enable: true,
  // 下面每一项 = 设置面板里的一个开关/滑块；false 表示该项对用户不可见（配置里仍可用默认值）
  panels: { view: true, weather: true, time: true, reader: true, perf: true, font: true },
}
```

`cabin/systems/ui/SettingsForm.js` **由 schema 自动生成控件**并**自动持久化**（`ArtLine-Part/02` §3.7 已设计）：

```js
export const settingsSchema = {
  'view.mode':      { type: 'enum',   values: ['fixed','tp','fp'], default: 'fixed', group: '视角', label: '默认视角' },
  'view.distance':  { type: 'number', min: 1.4, max: 7, step: 0.01, default: 3.2, group: '视角', label: '相机距离' },
  'blog.fontSize':  { type: 'number', min: 14, max: 22, step: 1, default: 17, group: '阅读', label: '正文字号' },
  // 每个模块贡献自己的设置项，UI 无需改动
}
```

> **配置（`src/config/*.config.js`）= 默认值 + 可见性；设置面板 = 运行时覆盖，存 `localStorage`（前缀 `cabin:`）。**
> 这与 Firefly 的分工完全一致。

### 3.6 验收（配置编排专项 `CF1`–`CF4`）

| # | 验收项 | 判定方式 |
|---|---|---|
| **CF1** | 关掉 `modules.config.js` 里**任一**模块 → 构建成功、场景无报错、该模块代码不被请求 | 18 次构建/启动 + Network 面板核对 |
| **CF2** | 新增一个配置项 = 改 1 个文件 + 加 1 个字段；设置面板**自动出现**该控件并自动持久化 | 端到端 |
| **CF3** | `src/config/README.md` 的清单与实际文件**一一对应**；删除某个已上线模块的配置文件会导致**构建失败** | 静态检查 + 构造测试 |
| **CF4** | `config/**` 未 import `cabin/**` / `blog/**` / `features/**`（不变量 `N11`）；代码里不存在该模块的可调常数 | 静态 import 图检查 + 评审 |

## 5. 批次顺序与可裁剪优先级

### 5.1 批次（`J7` 内）

| 批次 | 模块 | 为什么这个顺序 |
|---|---|---|
| **P1** | M01 内容存档 | **由 `J6` 落地**——它定义"内容怎么进来、怎么被读"，工时计入 `J6` 不在 `J7` 重复计算 |
| **P2** | M02 · M03a · M03b · M04 | 内容能被**找到**（时间 / 关键词 / 随机 / 主题）——博客的最低可用形态 |
| **P3** | M08 · M10 · M07 | 站点具备**社交面与身份** |
| **P4** | M11 · M13 · M16 · M17 | 氛围与个性化；**M17 是配置面板的落点**，做完 `CF2` 才算真验收 |
| **P5** | M12 · M14 · M15 | 外部世界；依赖外部服务，默认关 |
| **P6** | M06 · M05 · **M18** | 长尾收尾；**M18 是通道 A 的首个真实用例**，用于验证四通道模型 |

### 5.2 可裁剪优先级（时间/精力不足时按序砍）

```
第一批可砍：M17 显示设定、M16 字体设定（纯工具，不影响内容）
第二批可砍：M14 热点榜（依赖内网服务，Q17）、M12 影音收藏（4 平台默认全关，Q10）
第三批可砍：M05 创作管线（3D 里写作意义有限，Q14）、M06 关于本站（内容可选）
第四批可砍：M10 照片相册（只有 2 项功能，但语义纯）
第五批可砍：M18 背单词（独立，不影响任何内容能力）
```

**不可砍**：`M01`（核心）、`M02`（时间轴）、`M04`（主题）、`M08`（博客的社交面）。
**不可省**：`J2` 的全部基础设施（尤其风险 `R1` 的视角可达性）。
