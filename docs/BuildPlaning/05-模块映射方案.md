# 05 · 模块映射方案（使用说明）

> **映射的真源是 [`mapping.yaml`](./mapping.yaml)，不是本文档。**
> 本文档只回答三件事：**字段是什么意思**、**现在是什么状态**、**怎么改**。
> （不复制映射表格——那会立刻产生两份真源。）

---

## 1. 为什么映射单独留成 `mapping.yaml`

| 目的 | 为什么 YAML |
|---|---|
| **便于作者修改** | 纯文本、结构化、带中文注释；改一个字段不影响其他内容；不需要读懂表格里的换行折行 |
| **便于模型读取** | 字段名稳定、取值是**封闭集合**（`status` / `tier` / `channel` / `mode`），模型可以按 id 精确取用而不产生歧义 |
| **避免文档漂移** | "承载物品 / 交互 / 呈现通道 / 状态"只写一次；其余文档只引用不复制 |

## 2. 字段说明

### 2.1 标识与状态

| 字段 | 取值 | 说明 |
|---|---|---|
| `id` | `M01`…`M18` | 与 `Blog-Part` 的模块编号一致；`M18` 是本路线新增 |
| `name` | 字符串 | 模块名 |
| **`status`** | `proposed` / `confirmed` / `shipped` / `dropped` | ★ **作者改这一项来拍板**：`proposed` = 建议方案；`confirmed` = 可以开工；`shipped` = 已上线；`dropped` = 确认不做 |
| `batch` | `P1`…`P6` / `null` | 开发批次（见 [`04`](./04-模块增量开发与配置编排.md) §5.1） |
| `tier` | `T1`/`T2`/`T3`/`T4` | 物品归位类型（来自 [`Blog-Part/03`](../../../docs/Blog-Part/03-映射契约与交互规范.md) §2） |

### 2.2 承载物品

| 字段 | 说明 |
|---|---|
| `item` | 承载物品（"主 + 控制器"两件也可以，例如 M02 的地毯 + 台历） |
| `itemRef` | 物品在源码里的位置：**原 `index.html` 行号 → 迁移后的目标文件**。搬迁期靠它定位，搬迁后靠它追溯 |
| `mount` | **挂载点 ID**，必须在 `src/cabin/app/mounts.js` 注册。物品与模块**只通过挂载点 ID 相认**（不变量 `N2`/`N3`） |

### 2.3 呈现（决策 2 的落点）

| 字段 | 说明 |
|---|---|
| `render.channels` | **四通道**数组：`B`（CSS3D 真 DOM）/ `A`（Canvas 贴图）/ `T4`（状态量）/ `D`（DOM 覆盖层）。**可以多选**；选型判据见 [`03`](./03-渲染通道与构建选型.md) §4.2 |
| `render.detail` | 该通道具体怎么用（尺寸、重绘时机、退化行为） |
| `render.notes` | 约束与坑 |

> **改 `render.channels` 是"重做这个模块"级别的大改**。如果只是想调外观，改 `src/config/<模块>.config.js`。

### 2.4 交互

| 字段 | 说明 |
|---|---|
| `interaction.mode` | `aim` / `proximity` / **`both`**。★ 每个模块的主入口**必须是 `both`**——否则在默认固定视角下点不开（风险 `R1`，验收 `BB2b`） |
| `interaction.aimLabel` | 准星射线下的提示文案（**必须语义化**，不得是"交互"） |
| `interaction.proxLabel` | 近距判定下的提示文案（建议用引导性文案） |
| `interaction.activate` | 激活后的动作序列（尽量复用**已有**动画） |
| `interaction.exit` | 退出与归位（可选） |

### 2.5 接口与依赖

| 字段 | 说明 |
|---|---|
| `commands` | 该模块调用/提供的命令名，**沿用 [`Blog-Part/03`](../../../docs/Blog-Part/03-映射契约与交互规范.md) §5.1 的命名表**，不另起一套 |
| `data` | 数据来源（决定纯函数模型 `model.js` 与数据适配 `data.js` 怎么写） |
| `configKeys` | 该模块用到的配置键；必须落在 `src/config/<模块>.config.js` |
| `impl` | 实际落地位置（`S9` 回填） |
| `depends` | 前置条件（阶段或模块 id）。**依赖未就绪的模块不要提前开** |
| `estimate` | 预估人日（`S2`–`S8` 合计） |
| `accept` | 验收项编号（`BB*` / `CH*` / `CF*`）+ 该模块专项检查 |
| `notes` | 备注 / 偏差留痕 / 待确认项 |

### 3.1 四个必须知道的号码

| 号码 | 含义 |
|---|---|
| **`B` 只用于 2 个条目** | 通道 B（CSS3D 真 DOM）的成本在"分层"，只有**需要读的长内容**才值得——目前只有 `M01` 文章正文与 `M06` 关于页 |
| **`A` 覆盖 11 个条目** | 通道 A（Canvas 贴图）是**默认选择**：小体量、只读、不需选中。**`M18` 背单词是它的首个真实用例** |
| **`T4` 覆盖 9 个条目** | 通道 T4（状态量）**不需要交互预算**，是"免费"的信息传达，最被低估 |
| **`D` 覆盖 14 个条目** | 只要涉及**输入 / 长列表 / 复杂控件 / 无障碍**，就必须有通道 D——**它无法被裁掉** |

### 3.2 批次视图

| 批次 | 模块 | 一句话 |
|---|---|---|
| **P1** | `M01` | 内容骨架（由 `J6` 落地） |
| **P2** | `M02` `M03a` `M03b` `M04` | 内容能被**找到**：时间 / 关键词 / 随机 / 主题 |
| **P3** | `M08` `M10` `M07` | 站点具备**社交面与身份** |
| **P4** | `M11` `M13` `M16` `M17` | 氛围与个性化（`M17` 是配置面板的落点） |
| **P5** | `M12` `M14` `M15` | 外部世界（依赖外部服务，默认关） |
| **P6** | `M06` `M05` `M18` | 长尾收尾（`M18` 验证四通道模型） |
| **—** | `M09` | **不映射到场景**（`batch: null`）：打赏按钮只保留在文章页底部，0.2 人日随 `J5` 一起做 |

## 4. 怎么改映射（作者操作手册）

### 4.1 只想调外观参数 → 不要改 `mapping.yaml`

上线之后，日常调整一律改 `src/config/<模块>.config.js`（对齐 Firefly 的"用户唯一需要看的目录"）。
例：书架排序方式、书脊厚度公式、阅读器字号、长文阈值、相册列宽……

### 4.2 想换一件承载物品 → 改 `mapping.yaml` 的 4 个字段

```yaml
- id: M04
  item: "左墙试剂药水架（7 个试剂瓶）"        # ← ① 改物品描述
  itemRef: "原 L2205–2245 → cabin/world/floor1/reagentRack.js"  # ← ② 改源码位置
  mount: "reagent/rack"                      # ← ③ 改挂载点 ID（记得在 mounts.js 注册）
  interaction:
    aimLabel: "「标签名 · N 篇」"             # ← ④ 改提示文案
  status: proposed                           # ← 拍板后改成 confirmed
```

### 4.3 想改呈现方式 → 改 `render`

```yaml
  render:
    channels: [T4, A, D]      # ← 四通道，可多选；判据见 03 §4.2
    detail: >-
      改这里写清楚每个通道承担什么、什么条件下退化
```

> ⚠️ **`channels` 里加 `B` 之前先想清楚**：通道 B 需要 CSS3D 的分层与装填时序（四个硬约定），
> 成本是一次性的但只在"需要读的长内容"上划算。**小体量内容请优先 `A`。**

### 4.4 想新增一个模块 → 追加一个完整的 `- id:`

```yaml
  - id: M19
    name: "新模块名"
    status: proposed
    batch: P6
    tier: T1
    item: "承载物品（优先复用现有道具，必需新增 = 0 是目标）"
    itemRef: "原 L???? → cabin/world/.../xxx.js"
    mount: "xxx/yyy"
    render: { channels: [A, D], detail: "…", notes: "…" }
    interaction: { mode: both, aimLabel: "…", proxLabel: "…", activate: "…" }
    commands: ["xxx:open"]
    data: "数据来源"
    configKeys: ["xxx.*"]
    impl: null
    depends: []
    estimate: 1.0
    accept: []
    notes: ""
```

并同步：① 在 `src/config/modules.config.js` 加一行开关；② 在 `src/config/README.md` 加一行说明；
③ 在 `04` §5.1 的批次表里登记（如果需要）。

### 4.5 决定不做 → 不要删

把 `status` 改成 `dropped`，在 `notes` 写清原因。
**保留记录的价值是避免同一件事被反复讨论**（例：`M09 打赏` 就是不映射，理由写在 `notes` 里）。

## 5. 变更流程（谁改、什么时候改）

| 时机 | 改什么 | 谁改 |
|---|---|---|
| 拍板某个模块的映射 | `status: proposed → confirmed` + 相关字段 | **作者** |
| 开发完成 | `status: confirmed → shipped` + 填 `impl` + `notes` 写偏差 | 开发者 |
| 实现后想调参数 | **不改这里**，改 `src/config/<模块>.config.js` | 作者 |
| 发现实现与映射不符 | 改 `mapping.yaml` 并写清原因，**不要偷偷改实现** | 开发者 + 作者确认 |
| 决定不做 | `status: dropped` + `notes` 写原因 | 作者 |

### 5.1 门禁（防漂移）

| 检查 | 判定 |
|---|---|
| `status: shipped` 的模块数 == 运行时已注册的模块数 | CI 读 YAML + 运行时统计 |
| 每个 `status: shipped` 的模块都有对应的 `src/config/<模块>.config.js` | 静态检查（验收 `CF3`） |
| 每个 `status: shipped` 的模块的 `interaction.mode` 都是 `both` | 静态检查（验收 `BB2b`） |
| `modules.config.js` 的键集合 == `mapping.yaml` 的 id 集合 | 静态检查 |

任何一条不成立 → **构建失败**（对应风险 `R30`：`mapping.yaml` 与实现漂移）。
