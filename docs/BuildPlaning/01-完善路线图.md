### 2.1 关键路径与并行

```
J0 ──► J2 ──► J3 ──► J6 ──► J7 ──► J8        ← 关键路径
        │        ▲       ▲
        │        │       │
        ├─► J4 ──┘       │
        │                │
        ├─► J2.5 ────────┤
        │                │
J1 ─► J1.5 ─► J5 ────────┘
```

| 可并行组合 | 条件 | 收益 |
|---|---|---|
| `J1.5` + `J5` ‖ `J2`/`J3`/`J4` | 前者只动 `src/pages`、`src/content`、`astro.config` 与 `scripts/`，与 `src/cabin/**` 零冲突 | 两人时省 8–10 人日 |
| `J2.5` ‖ `J3` | 配置层是叶子目录，物件搬迁不引用它 | 省 2–3 人日 |
| `J7` 内各模块 ‖ 彼此 | 每个模块一个目录 + 一个配置文件；批次内可换序 | — |

> ⚠️ **唯一不可并行的**：`J2` 的 `CameraRig` 与统一 `Interactable` 是 `J6` 的前置；
> 缺了它们，阅读器只能做"点一下原地弹层"，方案 B 的"走进书页"转场无法实现。

### 2.2 ★ 编号约定（读本文档前先看这一节）

**`Jx.y` 这个写法在本项目里有两种含义，它们在 `J2.5` 处撞了号** —— 这是历史遗留，不是笔误：

| 形式 | 含义 | 例子 |
|---|---|---|
| `Jx` | 一个**阶段** | `J0` / `J1` / `J2` / `J3` … |
| `Jx.5` | **阶段之间的插层子阶段**（`.5` = 插在两个整数阶段之间） | `J1.5` 构建与内容地基、`J2.5` 配置编排层 |
| `Jx.y`（`y ≠ 5`） | **阶段内的第 y 项任务** | `J2.1` 线稿几何 DSL … `J2.10` 天气解耦 |

**成因**：骨架继承自 [`improve/07`](../../../docs/improve/07-最终定位与重构方案.md) §5 的 `J0`–`J8`
（那里**没有**阶段内编号）；本目录一边为 `J2` 细化出 10 项任务（引入 `J2.1`–`J2.10`），
一边又新增了两个插层子阶段（`J1.5`、`J2.5`）—— 两套编号共用一种形式，于是在 `y = 5` 处撞车。

| 撞号处 | 含义 A（阶段内任务） | 含义 B（插层子阶段） | 状态 |
|---|---|---|---|
| **`J2.5`** | **应用内核**（`App` / `EventBus` / `Registry` / `UpdateScheduler` / `Feature`） | **配置编排层**（`src/config/` 接线 + `SettingsForm`） | A ✅ 已完成（`v0.2.0-dev.5`）／ B ✅ **已完成（2026-09-15）** |
| `J1.5` | ——（无同号任务） | 构建与内容地基（Astro 落地） | ✅ 已完成 —— **不撞号** |

**执行时怎么区分**（写分支 / tag / 文档时务必照做）：

| 场合 | 约定 | 实例 |
|---|---|---|
| 任务分支 | `task/J2.5-<短名>`，**短名必须写** | `task/J2.5-core-kernel`（内核 ✅）／ `task/J2.5-config-layer`（配置层 ✅） |
| 结果文档 | 沿用任务号 + **撞号时后者加后缀** | `docs/实施结果/J2.5-实施结果.md`（内核）／ `docs/实施结果/J2.5-配置编排层-实施结果.md`（配置层） |
| dev tag | ★ 用 `pnpm task:done <任务号> --base=0.2.0` **显式指定阶段版本号** | 见 [`VERSIONING.md`](../VERSIONING.md) §11 的 `--base` 说明 |

> ⚠️ **一处与预期不符的事实（2026-09-15 补记）**：上表原先写"两者时期不同，**文件名不会同时存在**"，
> 但实际执行下来两份结果文档**确实同时存在**了 —— 所以配置层那份**加了后缀**（`-配置编排层-`），
> 而不是去改已归档的内核版文件名。**约定随事实更新，历史不动。**

> **为什么不干脆改号**：`J2` 的 10 项任务已全部归档（文件名、tag、提交信息里都是 `J2.x`），
> 改名要动 10 个文件名与约 60 处引用，收益仅仅是"好看"；
> 而 `J1.5` 用同一套 `.5` 规则且**并不撞号** —— 只改一边反而破坏一致性。
> 因此选择**把约定写清楚**，而不是事后改号。

#### J1.5 实施要点（已完成，供后续阶段参照）

| 项 | 结论 |
|---|---|
| 岛的写法 | 路线图原写 `client:only` —— 那需要**真实前端框架渲染器**做 hint，本项目没有；`client:load` 对 `.astro` 组件也无效。**正确写法是不加任何指令**（Astro 组件的 `<script>` 本来就只在浏览器执行、天然不 SSR）。岛仍然唯一：只有 `CabinMount.astro` import `cabin/boot.js` |

**★ 本目录新增要求：挂载点 ID 表（`cabin/app/mounts.js`）**

物件**不 import 任何功能模块**，它只声明自己的挂载点 ID 与"发什么命令"：

```js
// cabin/world/floor1/bookshelf.js
export default defineProp({
  id: 'floor1/bookshelf',
  mount: 'shelf/main',                       // ← 挂载点 ID，由 features/* 认领
  interactables: () => [
    { id: 'shelf/browse', label: '浏览书架', mode: 'both',
      anchor: MOUNTS['shelf/main'].anchor, radius: 1.8,
      onActivate: (ctx) => ctx.commands.run('shelf:open', { shelf: 'main' }) },
  ],
})
```

这样 `world/**` ⇄ `features/**` **互不 import**（依赖不变量 N2/N3，见 [`02`](./02-架构与目录调整.md) §5）。
