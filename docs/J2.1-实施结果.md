## 1. 做了什么

把全屋几何的构造原语从 `legacy/monolith.js` 提取为 4 个模块：

| 模块 | 内容 | 来源（monolith 行） |
|---|---|---|
| `core/geometry/sketch.js` | `V` `geo` `line` `iline` `dline` `edge` `box` `log` `put` `logBetween` | 原 230–251 |
| `core/geometry/roundBox.js` | `roundBoxGeo` `rbox` | 原 714–737 |
| `core/geometry/solid.js` | `lloop` `solid` `solidCyl` | 原 747、749–762 |
| `core/geometry/shapes2d.js` | 7 个纯点集函数 + `lineFromPts` `segsFromPairs` | 原 6365–6379 |

**迁移量**：`monolith.js` **9077 → 8586 行（净 −491）**；新增 4 个模块共约 330 行（含文档注释）。
**语义**：实现零改动 —— 阈值（棱边 `1`、`rbox` 用 `12`）、段数（圆柱 8 边、圆角 `seg*2+1`）、
退化判据（`1e-9`）、四元数对齐方向，全部逐字照搬。

## 2. 关键设计：依赖注入

几何层天然依赖 `scene` 与材质，但 `core/**` 不许持有它们（不变量 `N1` / `N7`），
因此 4 个模块都是**工厂**，依赖显式注入：

```js
const { V, geo, line, iline, dline, edge, box, log, put, logBetween } = createSketch({
    scene,
    materials: { line: MAT, inner: IN_MAT, dash: DASHMAT, fill: FILL },
});
```

| 决定 | 原因 |
|---|---|
| 材质用**中性名**（`line` / `inner` / `dash` / `fill`） | `MAT` / `FILL` 是业务命名，留在 monolith；`core/` 只认形状 |
| `solidCyl` 的默认材质**注入** | 原实现硬编码具体物件（猫）的材质 `CATMAT`；现在由调用方传 `defaultSolidMaterial`，**行为不变而 `core/` 干净** |
| `shapes2d` 的 7 个点集函数**直接 export**（工厂外） | 它们是零依赖纯函数（三角函数 → 点列），可直接单元测试；只有 `lineFromPts` / `segsFromPairs` 需要 `V`，才走注入 |
| 解构保留**原标识符名** | 文件内 2000+ 处调用点（`box` / `log` / `put` / `edge` …）一行都不用改 |

`edge()` 是这一层的核心原语：**填充面 + 棱边线**的分组 —— 线稿风格画面的唯一规则实现，
`box` / `log` / `rbox` / `solid` 都建立在它之上。

## 4. ★ 判据维护：**扩大适用面**（而不是降级）

`J2.4` 时 `verify-f06` 的链条是"必然断裂 ⇒ 降级为参考项"。这次不同：

`verify-migration` 的【④ 关键标识符计数】断言"源文件里 `new THREE.Mesh(` 184 次 =
当前实现里也是 184 次"。J2.1 之后 monolith 里少了 3 个 `Mesh(` 与 2 个 `Group(` ——
**不是回归，是搬走了**。处理办法是**把扫描范围从「monolith + dom.js」扩到
「源自 monolith 的实现所在目录」**：

```
legacy/ + core/ + systems/ + world/ + props/ + dom.js      ← 计入
app/** 与 boot.js                                          ← 排除（F0.2/F0.3/J1 新增的基础设施）
```

- **强度不降**：搬运不改变总数，只有真的增删几何/交互/监听才会让计数变化；
- **为什么排除 `app/**` 与 `boot.js`**：它们不是从源文件搬来的
  （例如 `boot.js` 自带 1 个 `addEventListener`，计入后"源文件 vs 当前"永远差一截 ——
  本次实测先是 `addEventListener 51 → 52`，正是这个原因）。

> 这条规则对后续任务同样成立：`J2.2`（materials）、`J2.3`（lighting）、`J2.6`（interaction）
> 都是往 `core/` `systems/` 里搬，计数自动守恒；`J2.5`/`J2.8` 往 `app/` 加内核，不计入。

## 5. 新增：单元测试地基（`tests/unit/`）

`tests/visual/README.md` 写着「`tests/unit/` 自 `J2` 起」。本次建成，且**零新依赖**
（与 `J0.4` 的取舍一致：用 Node 22+ 自带的 `node:test`，不引入 vitest/jest）：

| 项 | 内容 |
|---|---|
| 运行 | `node --test "tests/unit/*.test.mjs"`（已加入 `package.json` 的 `test:unit`） |
| 覆盖 | `shapes2d` 的 7 个纯点集函数：点数、半径、首尾角度、单调性、边界 |
| 结果 | **8 项通过 / 0 失败** |

为什么先测它们：这 7 个函数是 24 层魔法阵的唯一来源，回归时像素对比只会说"不一样"，
单元测试能直接指出**错在哪一个函数**。

> ⚠️ 注意：`node --test tests/unit/`（目录形式）在本机 Node 24 上会被当成模块入口而
> `MODULE_NOT_FOUND`；必须用 **glob 形式**。脚本已按 glob 写入。

## 8. 一句话总结

**把 491 行几何原语从 monolith 里搬进 4 个模块，画面逐字节未变** ——
依赖注入让 `core/` 同时满足了"不碰具体物件"与"不持有全局场景"，
而计数判据靠**扩大扫描范围**（而不是放宽）跟上了搬迁期的语义。
