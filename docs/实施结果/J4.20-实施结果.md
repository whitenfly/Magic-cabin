### 2.1 ★ 四段合并为什么是**帧顺序等价**的

四段在原 `tickOnce()` 里**本来就是连续的**（L6425 → 纸堆块结束，中间只隔空行），
在 `FrameBody.js` 里对应 `frame/27` / `frame/28` / `frame/29` / `frame/30` 四个**相邻**任务，
中间没有别的帧任务 ⇒ 合并成一个任务后，**每帧的执行序列逐项不变**。

合并后**只在 `frame/27` 的位置登记一次**，后三个任务已删除（原地留注释说明去处）。

### 2.2 必要的局部改名（只影响局部变量，数值不变）

`update(dt, time, s, …)` 的 `s` 是 state，原代码里有两处局部 `const s` 会遮蔽它：

| 原 | 现 | 位置 |
|---|---|---|
| `const s = 0.16 * pop * (1 + …)` | `const sc = …` | 魔法符号缩放 |
| `const s = (ti - 0.18) / 0.60` | `const sc = …` | 纸堆环飞进度 |

两处都只改**变量名**，公式与取值一字未改。

## 3. 判据与证据

### 3.1 画面：3/3 机位逐字节相同 ✅

### 3.2 ★ 「未定义的自由变量」的实证：`tsc` 与 `build` 全绿，页面却起不来

搬到一半时：

```
✓ tsc --noEmit        （0 错误）
✓ astro build         （8 page(s) built）
✗ tests/visual/compare → 等待超时（120000ms）: document.documentElement.dataset.cabin === "ready"
```

页面诊断（`scripts/oneoff/_j3-diag.mjs`）立刻给出根因：

```
ReferenceError: startQuill is not defined
```

**成因**：`installFloor1` 开头有一行 J4 段切片留下的跨段导出：

```js
ctx.makeCup = makeCup; ctx.makeChair = makeChair; ctx.startQuill = startQuill; ctx.makeCushion = makeCushion;
```

它靠**函数声明提升**引用 `startQuill` —— 而 `startQuill` 是 12.11b 区间内的**局部函数**，
已随置物台搬进新模块。全局搜索确认 `ctx.startQuill` **没有任何读者**，故删除该分句。

> 这是 `J4.9` §2.3 坑③ / `J4.14` §0.2 的同一条教训的**再次实证**：
> **`tsc` 与 `build` 都查不出"未定义的自由变量"，只有页面起不来才会暴露。**
> ⇒ 凡切开函数边界的任务，**必须**跑一次页面诊断（约 20 秒），不能只看静态门禁。

### 3.3 ★ 新建永久判据 `test:cart`：四段动画原本**一条判据都没有**

合并四段是本次最大的结构改动，但**静止帧里四个状态全是休眠的**：

| 状态 | 静止值 | 谁能唤醒 |
|---|---|---|
| `cartOut` / `cartP` | `false` / `0` | 点车体 → 滑动 |
| `quillRun` | `0` | 点墨水瓶 / 羽毛笔 → 书写 |
| `paperRun` | `0` | 点纸堆 → 纸堆起飞 |

⇒ 像素回归（没人去点的定格帧）、探针（只问"有没有 aim 入口"）、冒烟（点的是壁炉与书堆）
**三条一起漏**。这与 `J4.8` 的镜面涟漪是**同一类静默回归**，
故照 `test:mirror` 的样子建 `tests/e2e/cart-shelf.mjs`：

```
【机位 top】点击点 {"x":450,"y":300}
  对照（不点击，推 40 帧）：差异像素 9
  实验（点置物台，推 40 帧）：差异像素 73579
✓ ★ 点击置物台后画面**显著**变化（四段动画至少有一条被唤醒）  →  命中机位：top
✓ ★ 命中机位的对照组可忽略（差异确实来自点击，不是环境动画）  →  干净机位：top
```

**实测踩到的两个坑（都写进脚本注释）**：

1. **必须先预热**（`step(60)`）—— 页面刚 `ready` 时环境光 / 天气插值还在过渡，
   不预热则第一台机位的"对照"自己有 3868 像素变化，判据被搅浑；
2. **对照组判据只能对"命中机位"提要求** —— 未命中的俯视机位视野里有**持续动画**
   （云在飘、星星在闪），它的对照本来就大（实测 4781）。拿它当判据只会**假红**。
   脚本改为"至少一台机位显著命中 + 至少一台机位的对照可忽略"。

### 3.4 探针：交互通路逐条完好

```
✓ ★ 搬迁物件的准星入口齐全  → 28 件有准星入口：… floor1/cart-shelf …
✓ ★★ 每条声明了 aim 的交互都有自己的命中体  → 75 条交互各有 aim 入口
```

**`magicMeshes=744`**（`props=37`、`interactables=84`）：

- 原 4 处 `regMagic` 的命中体是 `o.traverse(m => m.isMesh && !m.userData.noHit)`
  （`world/house/shell.js` L265–271），新路径 `hits` 的遍历条件**完全相同**
  ⇒ 4 个部件的命中体数量**逐条一致**，总数不变（仍是 744）。

### 4.2 ★ 另一项红**不是**预期的：`verify-migration` 的 `regMagic(` 计数白名单

`task:done` 第一次被这一步**中止**（合并未发生）：

```
✗ regMagic(  64 → 43  → 已知差 -17
✗ verify 失败：1 个脚本有断言未通过 ⇒ 已中止合并
```

**根因（分解到每一处）**：`scripts/verify-migration.mjs` ④ 用"原始 monolith → 当前 `src` 拼接"
的**调用点计数差**守"`regMagic` 是否真被 `interactables` 取代"，白名单写着 `-17`（J3 的成果）。
本阶段两次搬迁的**净变化**是：

| 任务 | 净变化 | 明细 |
|---|---|---|
| `J4.20` `cart-shelf` | **−4** | `install.js` 里删掉 4 处 regMagic 调用 |
| `J4.19` `bookshelf` | **0** | 删 1 处，但新模块的行注释里又添回 1 处同名字面量 ⇒ 抵平（见下） |

⇒ 期望值应为 **−21**（`−17 − 0 − 4`）。已按脚本 L174 的明文要求
（"后续阶段再动这些调用点时，一并更新这里的期望值并在结果文档里说明"）
更新为 `-21`，**判据强度不变** —— 它守的仍是"有没有人**偷偷加** `regMagic`"
（那会让计数**上升**，当场变红）。

> ⚠️ **顺带发现判据自身的一个粒度缺陷（已记为遗留，本次不动）**：
> `stripComments()` 只剥**块注释**（`/* … */`），**不剥行注释**（`// …`）。
> 而每个 `defineProp` 模块的文件头/行内注释都会提到这些字面量
> —— 于是"删掉 1 处代码 + 写 1 行解释注释"= 计数**不变**，搬迁在判据上"看不见"。
> 本次不改它：改它会牵动另外 7 个计数的期望值，风险大于收益；只在白名单里如实写出分解。

## 6. 遗留与交接

1. **`test:cart` 只验证"至少一条通路活着"**。它用两台机位各点一次屏幕中心，
   命中哪个部件取决于射线 —— **没有**逐条区分"滑动 / 书写 / 纸堆"。
   要逐条验证需要各部件独立的近距离机位（可后续补）。
2. **碰撞表的正确性仍无自动判据**（`J4.19` §6.1 已记录，本任务再次确认）：
   `movingPlatforms` 改的是**数据来源**（`ctx.cartG` → `ctx.cartShelfApi.parts.cartG`），
   数值与语义都没变，但**没有任何门禁能证明这一点** —— 靠的是"部件就是同一个 `cartG` 实例"。
3. **`GLYPH_CHARS` / `GLYPH_COLORS` 留作 `build` 内局部常量**（只有 `build` 用）；
   其余常量经 `parts.consts` 交出。若后续要复用，再考虑进 layout。
4. 批 1 剩余组：`teapot` 组 · `astro+veil+star-particles` · `board` · `wand` ·
   `magic-book` · `desk-chair` · `decor-loop`（单独判定）。
5. **`verify-migration.mjs` 的 `stripComments()` 不剥行注释**（§4.2）——
   判据的粒度缺陷：搬迁代码 + 写解释注释 = 计数抵平，"搬迁在判据上不可见"。
   修它会牵动另外 7 个计数的期望值，留给后续任务决定。
