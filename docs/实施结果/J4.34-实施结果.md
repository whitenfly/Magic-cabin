## 1. `SKIP` 记的两条前置，逐条兑现

`floor1-teapot.SKIP.md` 把这一带判为"互相咬合的三块"，并给出两条前置：

| `SKIP` 记的前置 | 谁兑现的 | 本件怎么用 |
|---|---|---|
| ① `makeCup` / `cups` 抽成共享工厂（`cups` 被暖桌与茶壶共用） | `J4.26`（`props/cup.js`） | 经**装配选项** `installProp(teapot, { ctx: { cupFactory } })` 拿到它，借 `cups[2]` 当倒水目标 |
| ② `_tv` 私有化（原 `ctx._tv` 被茶壶与暖桌抢） | `J4.28`（暖桌自造一份）+ **本件** | 本件自造一份 ⇒ **共享临时量归零** |

`SKIP` 原本还列了第三条"每件一个 `THREE.Vector3`"的处置 —— 本件正是它的**收尾**。

### 1.1 与茶杯的边界（**为什么茶杯的摆放不搬进来**）

3 只茶杯的摆放（`cupFactory.makeCup(DT_X ± 0.85, DT_Z + 0.20)` ×3）**留在 `install.js`**：

- 它们是**长餐桌**上的陈设（坐标取自 `DT_X/DT_Z`）；
- 本件只是**借用其中一只**当倒水目标（`const CUP_T = cups[2]`，与原实现一致）。

`CUP_T` 存的是**对象引用** ⇒ 茶杯被点击升腾时它的 `position` 是**活的**，每帧读到的仍是最新位置
—— 与原实现的行为一字不差。

## 2. 三个必须处理的技术点

### 2.1 ⚠️ `ctx.D2R` 不在装配环境里

原几何段用 `(20 + i * 14) * ctx.D2R`（提梁弧线的 11 个采样点），而 `D2R` 定义在
**`house/shell.js`** 的早段（`const RAIL_R = 1.24, RAIL_H = 0.85, D2R = Math.PI / 180;`），
`SKIP` 明确指出它"**不在 `propCtx` 的可用键里**"，给的处置是：

> 在模块里自己写 `const D2R = Math.PI / 180;`（同值，零差异）

本件照办 —— **只在 `teapot.js` 内可见**，不污染 `ctx`。（`shell.js` 的 `ctx.D2R` 导出仍保留，
它有自己的读者。）

### 2.2 ⚠️ `DT_*` / `DTOP` 要经 `L` 取

装配环境里**没有** `ctx.DT_X` 这类展开键，只有 `L`（layout 对象）
⇒ 一律写 `L.DT_X` / `L.DT_Z` / `L.DTOP`（不变量 `N9`，**数值一个没改**）。

### 2.3 `ctx._tv` 的两行被删除

```js
const _tv = new THREE.Vector3();
ctx._tv = _tv;
```

这两行原本在茶壶段，**却同时服务暖桌的收音机音符**（`J4.28` 之前）。
`J4.28` 让暖桌自造一份之后，`ctx._tv` 只剩茶壶一个用户 ⇒ 本件把它**删掉**，
茶壶在 `build` 里自造私有一份。

> 本件起草时曾误写成 `L_DTOP_of(parts)` 这类不存在的辅助函数（因为漏把 `DTOP` 放进 `parts.consts`）
> —— 在第一次自检时发现并修正。**记在这里**是因为它说明"逐字搬运时替身名不能现编"。
