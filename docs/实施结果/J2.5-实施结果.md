## 2. ★ 与 monolith 的接缝：`installCabin(app)`

搬迁期最有侵入性的一步，做法是**只包一层、不重写内部**：

```js
// 之前：模块加载即执行
(function () { 'use strict'; /* …8800 行… */ })();

// 之后：执行时机交给 boot，内核先于场景存在
export function installCabin(app) {
    const { registry, bus, scheduler } = app;
    (function () { 'use strict'; /* …一行未改… */ })();
}
```

`boot.js` 里：

```js
const app = createApp()
if (opts.stats) window.__cabinApp = () => app.stats()   // 与 __cabinRenderStats 同一个开关
const { installCabin } = await import('./legacy/monolith.js')
installCabin(app)
```

**为什么必须这样**：内核要先于场景存在（`Registry` 得在第一个物件被造出来之前就绪），
而"DOM 挂载 → 设测试开关 → 加载实现"的时序完全不变 ⇒ 像素逐字节相同。

## 3. `regMagic` 的接入方式（零行为改动）

```js
const magicMeshes = registry.magicMeshes;   // ★ 同一个数组实例
function regMagic(o, onClick) {
    o.userData.onClick = onClick;
    const meshes = [];
    o.traverse(m => { if (m.isMesh && !m.userData.noHit) meshes.push(m); });
    registry.registerMagic(o, meshes);      // 内部统一回填 magicRoot 并 push
    return o;
}
```

`aimRay()`（准星射线）与 `pointerup`（点击射线）仍直接用 `magicMeshes` 做 `intersectObjects`
—— **命中行为一个字节都没变**。这是「先集中，后改造」：`J2.6` 在注册中心上做统一契约时，
64 处 `regMagic` 已经都在表里了。

## 4. ★ 调度器的纪律：只登记，不改顺序

`UpdateScheduler.update()` **严格按登记顺序**执行，`tier`（`always` / `near` / `idle`）
在 `J2` 期间**只是元数据**，不做任何裁剪 —— 因为 `J2` 的判据是像素逐字节零差异，
而"跳过远处物件"恰恰会改变画面。按 tier 裁剪留给 `J8`（性能与低配档）。

现在就写下 tier 的理由：`J3`/`J4` 搬物件时每个 `defineProp` 都要声明更新档位，
顺手写下最省事，事后补要重新审一遍 67 件物件的更新代价。

> 因此 `J2.5` **没有**把 `tickOnce()` 里的 940 行搬进调度器 —— 那是 `J4` 的 DoD
> （「`animate()` 收缩为调度骨架 ≤ 60 行」）。本次只提供设施。

## 6. 新增测试：11 项内核契约

`tests/unit/kernel.test.mjs` 测的是**契约**，不是实现细节：

| 测试 | 守什么 |
|---|---|
| `on` 返回的取消函数可退订且**幂等** | `Feature.dispose()` 里一行退订，不必记住 type+fn |
| `emit` 对监听表**快照** | 回调里退订自己（一次性监听）不会漏掉后面的监听者 |
| `once` 只触发一次；无人监听时 `emit` 返回 0 | 0 是合法结果，不是错误 |
| `Registry` 拒绝重复 id | `J3` 搬迁时最能暴露"两处定义了同一个物件" |
| `magicMeshes` 是**同一数组实例** | 射线依赖这一点（复制数组会让命中集合错位） |
| `registerMagic` 回填 `magicRoot` | 射线命中后要靠它找到物件根 |
| 调度器：登记顺序 = 执行顺序 | `J2` 期间 tier 不裁剪（画面零差异的前提） |
| 调度器：`enabled=false` 跳过、恢复后可再用 | `J8` 的低配档会用它 |
| `defineFeature` 校验 | id 必填、钩子必须是函数 |
| `App.register` 的 `requires` 校验 | 依赖缺失**立刻**报错，不留到运行时 `undefined` |
| `App.start` 按 `order` 启动 + 生命周期状态 | `created → running → stopped → disposed` |

## 9. 一句话总结

**内核就位，画面未变** —— `J2.5` 把"谁持有状态、谁登记什么、谁按什么顺序跑"
这三件事从隐式变成显式：`Registry` 收拢了四套并行的收集方式，`UpdateScheduler` 把
"顺序即语义"写进了契约，`EventBus` 给了模块之间一条不靠共享闭包变量的通道。
从这一步起，`J2` 的 DoD「新增一盏灯 / 一个交互的**改动文件数 = 1**」才有地方落。
