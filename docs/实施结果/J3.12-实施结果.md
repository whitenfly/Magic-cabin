## 1 · 问题（L18）

**现象**：`ship main` 把**整份发布计划**（`switch` → `merge` → `add` → `commit` → `tag` → `push` → `switch`）作为「待执行命令」写入记录，于是那些**本应由模型经 `exec` 自动执行**的本地命令也被套上了 `[ ]` 复选框。

**为什么是缺陷**（三层）：

| # | 问题 | 说明 |
|---|---|---|
| 1 | **语义混淆** | 「待执行命令」区的原始设计是**人工待执行清单**（§12 的推送类），但发布计划里的本地变更类也混了进来 ⇒ "待执行"到底指人工还是模型，读者分不清 |
| 2 | **永久的 `[ ]` 噪音** | §9.2 明确 `isCommandDone()` **只认推送类**，其余（merge / tag / 计划类）**不自动标记** ⇒ 那几条本地命令**永远翻不成 `[x]`** |
| 3 | **会累积** | 实测：当前未执行的 `[ ]` 共 **17 条**，其中**只有 1 条**是 `git push`、**16 条永远翻不了**，分布在 **3 个以上**发布计划区块里 ⇒ **每次 `ship main` 都留下一批** |

**关键澄清**：这不是"工具要求人工执行它们" —— 规范 §8 / R10 明确要求**模型**经 `exec` 入口执行变更类命令。问题纯在**区块归类**。

## 2 · 修法（只让推送类进入「待执行」区）

```js
// ★ L18 修正：只有推送类命令进入「待执行命令」区。
//   本地变更类由模型经 exec 入口执行（§8 / R10），既不需要人工、
//   也永远无法被 isCommandDone() 自动翻 [x]（§9.2 只认 push 类）。
const pushCmds = cmds.filter((c) => /^git push\b/.test(c));
const flipped = appendRecord(
  buildEntry({
    task: `发布计划 v${ver}`, kind: 'ship', st,
    body: [
      '- 计划内容：`dev` → `main` 的 `--no-ff` 合并 + 正式版 tag',
      '- ★ **本地变更类命令（switch / merge / add / commit / tag）由模型经 `exec` 入口自动执行** —— 完整计划见上方输出（§8 / R10）',
      '- 下面**只列推送类命令**：只有它们需要人工在普通终端执行',
    ],
    note: '…',
  }),
  pushCmds.length ? pushCmds : null,
);
```

**完整计划仍然全部打印到 stdout**（人看得见），只是**不再写进带复选框的「待执行」区** ✓

## 3 · `GitPushHistory.md` 噪音清理（用户指示）

### 依据：规范**允许人工判断后标记**

§9.2 的判定表对这类命令写的是：

| 命令形态 | 翻转条件 |
|---|---|
| 其他命令（merge / tag / 计划类） | —— **不自动标记（人工判断）** |

⇒ **由人工（用户）判断后标记为完成，是规范允许的** ✓ 工具只是不代劳。

用户的判断依据：**「已完全推送所有修改和 tag」** ✓

### 执行

| 项 | 内容 |
|---|---|
| 范围 | **只把 `# [ ] ` 改为 `# [x] `**，**其余内容一字不动**（严格遵守用户约束） |
| 数量 | 清理前 `[ ]` = 22 条 → 清理后 = **0 条**（`[x]` 相应增加） |
| 备份 | `.cache/GitPushHistory.bak.md`（116,836 字节，在 `.gitignore` 内） |
| 编码 | 该文件**无 BOM**（前 3 字节 `35,32,71`），替换时保持 UTF-8 与原有换行符不变 |

### ⚠️ 如实说明这次标记的性质

严格讲，这几条**本地命令**的标记属「**人工确认该计划已完成**」，而**不是**「git 状态逐字证明了那条命令被执行」：

- 它们**确实以等价形式执行过**（`J3.7` 发布时由模型经 `exec` 完成）✓
- 但个别命令的**文本与实际不完全一致**（例：计划里是 `git tag -a v0.3.0 -m "v0.3.0 正式版"`，实际打的是 `-m "J3 物件模块化（35/67 件…）"`）
- 且其中 2 份计划是**过时的"重复发布 v0.3.0"**（L16 的产物，已修）

⇒ 采用 §9.2 的「**人工判断**」通道处理，**如实记录于此**，不谎称是工具自动证明的。
