## 1. 做了什么

### 1.1 `audio` 段搬迁

| | |
|---|---|
| 原位置 | `legacy/monolith.js` L129–L151（21 行，`const SND = (() => { … })()`） |
| 现在住哪 | `src/cabin/systems/audio/AudioSystem.js`（`export function installAudio(ctx, app)`） |
| import | 0 条 —— 它只依赖 `store`（由 `--move` 从 `app` 自动解构）与 `Audio` / `document` 等 JS 全局 |
| monolith 侧 | 只剩一行 `installAudio(ctx, app);` |

`SND` 是**被全文引用**的一段（`SND.play(...)` 在 monolith 里出现 18 次）—— 它们现在全部走
`ctx.SND.play(...)`，由段末的 `ctx.SND = SND` 提供。`--check` 逐引用复算通过（0 处绕过 `ctx`）。

### 1.2 段表：18 个剩余段的目标模块一次填好

本次**一次性补齐全部 21 段**，并写进段表头：**一个段一个文件**（两段写同一文件会互相覆盖）。

### 2.1 ★ 一处门禁判据的**范围**必须跟着实现走（`verify-migration`）

段切片把 `SND` 的实现搬出 monolith 之后，`verify-migration` 的这条判据失败了：

```js
// 范围是 `mono`（只读 legacy/monolith.js）
const codeOnly = mono.replace(…)
check('音效路径保持相对 sounds/', /'sounds\/'\s*\+/.test(codeOnly))
```

**实现搬走了，判据的扫描范围没搬** —— 于是它变成"永远失败"。
处置有两条路，本次选了正确的那条：

| | 做法 | 后果 |
|---|---|---|
| ❌ | 因为文件搬了就把判据删掉 / 放宽成"随便匹配" | 音效路径从此无人守 —— 绝对路径或 CDN 混进来也不会红 |
| ✅ | **判据语义不变，扫描范围跟着实现走**（就地扫 `src/cabin/**` 的 6 个目录） | 仍能抓住"音效路径被改成绝对路径 / CDN" |

> 与 §2.4 的 `verify-f06` 是同一条原则的两种形态：
> **搬迁会让"按字面匹配某个文件"的判据失配；适配的是"名字/位置"，不是"强度"。**
> 每个 `J4.x` 都要预判自己会碰到哪几条，并逐条给出"为什么这样适配不放松判据"。

`J4.2` 验证了 `J4.1` 交付的流水线在**被全文引用的段**上同样成立（`SND` 有 18 处调用点，
