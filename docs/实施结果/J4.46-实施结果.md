## 0. 一句话结论

`stripComments` 从「**只剥块注释**的正则」换成「**块注释 + 行注释都剥**的逐字符状态机」：

> ★ **行注释里的字面量不再进计数** —— 判据从此只数**代码里**的调用点数。
> ★ 顺带修掉一个**真实 bug**：旧正则在当前源码上**误删了 1932 字符真实代码**（见 §3）。
> ★ 8 项计数里只有 `regMagic(` 受影响：**−35 → −52**（`64 → 12`）；其余 7 项在新旧口径下同值。
> ★ 三条负例实测（含"真调用必须变红"），见 §5。

## 1. 问题：行注释污染计数的**两种失真**（都是实测踩出来的）

判据的形态是「**源文件**（上游单文件 `index.html`）与**当前 `src/cabin/**` 拼接文本**跑同一条正则，
比较差值是否等于白名单」。它先剥注释再数 —— 但旧的 `stripComments` **只剥块注释**：

```js
const stripComments = (s) => s.replace(/\/\*[\s\S]*?\*\//g, '')   // ← 不处理 //
```

于是 `//` 行注释里的字面量照样被算进计数：

| 失真 | 机制 | 本阶段的实例 |
|---|---|---|
| **正向（抵平）** | 删掉 1 处真实调用，又在行注释里写了同名字面量 ⇒ 计数**看不出来** | `J4.19` · `J4.21`（连"解释这个坑的注释"又踩一次）· `J4.36` · `J4.39` · `J4.41` · `J4.43` · `J4.45` —— 累计 **9 次** |
| **负向（多减）** | 删掉**整段**时，该段行注释里原有的字面量被一并删除 ⇒ 文本差 ≠ 真实差 | `J4.43` 首次：真实删 5 处 `regMagic` 调用，文本增量却只有 −3 |

`Math.random()` 还有额外一层：脚本先把 `runtimeRng()` / `textureRng()` 等 7 个种子随机源
**反向还原**成 `Math.random()` 再数 ⇒ 行注释里写带括号的 `textureRng` 也会 +1。

**噪声规模（实测）**：`src/cabin/**` 里 `regMagic(` 命中 **84 行**，其中 **17 处**在行注释里 ——
绝大多数是各 `defineProp` 模块文件头那张「原来住哪 → 现在住哪」的搬迁对照表。
**「注释写得越清楚，门禁越红」已经足以影响结论，所以本轮根治。**

## 2. 取证：新旧口径的**全部差异逐处可解释**

搬进正式脚本前先用一次性校验器取证（脚本已删，结论如下）。两侧文本：

| 侧 | 内容 | 字符数 | 剥掉段数（行 / 块） |
|---|---|---|---|
| **a 侧** | 上游 `index.html` **全文** | 556554 | 311（122 / 189） |
| **b 侧** | `src/cabin/**` 112 个 `.js` 拼接（rng 还原后） | 867721 | 1912（1209 / 703） |

**① 不误删**：状态机剥掉的**每一段**都以 `//` 或 `/*` 开头 —— 两侧均 0 例外。
（这一条是必须的：正则版的失败模式正是"把 `'http://…'`、`/a\/\//` 里的 `//` 当注释开头，**删掉真实代码**"。）

**② 计数变化可精确归因**：旧口径已剥块注释 ⇒「旧计数 − 新计数」**必须恰好等于**行注释里的出现次数。
实测**逐项成立**：

| 计数 | 旧 `a→b`（差） | 新 `a→b`（差） | 行注释中出现 | 等式 |
|---|---|---|---|---|
| `Math.random()` | 286 → 286（0） | 286 → 286（0） | **0** | ✓ |
| `new THREE.Mesh(` | 184 → 184（0） | 184 → 184（0） | **0** | ✓ |
| `new THREE.Group(` | 198 → 198（0） | 198 → 198（0） | **0** | ✓ |
| `new THREE.ShaderMaterial(` | 6 → 6（0） | 6 → 6（0） | **0** | ✓ |
| `regMagic(` | 64 → 29（−35） | 64 → **12**（**−52**） | **17** | ✓ `29 − 12 = 17` |
| `addEventListener(` | 51 → 49（−2） | 51 → 49（−2） | **0** | ✓ |
| `getElementById(` | 49 → 41（−8） | 49 → 41（−8） | **0** | ✓ |
| `SND.play(` | 22 → 19（−3） | 22 → 19（−3） | **0** | ✓ |

⇒ **只有 `regMagic(` 一项的口径值变了**，其余 7 项的字面量在行注释里出现 **0** 次 ⇒ 期望值不变。

## 3. ★ 顺带修掉的真 bug：旧正则**误删 1932 字符真实代码**

正则版不认识「字符串 / 行注释 / 模板串」，于是把**行注释里的路径通配**当成了块注释开头，
一路剥到**下一个 `*/`** —— 而那个 `*/` 可能在很远的地方（甚至**跨文件**）：

| 区间 | 起点 → 终点 | 成因 | 误删长度 |
|---|---|---|---|
| ① | `core/geometry/propTools.js@1909` → `core/geometry/roundBox.js@226` | 行注释 `` // 搬出 `world/**` 的物件… `` 里的 `/**` 被当成块注释开头（**跨文件**剥到 `roundBox.js` 的 JSDoc 结尾）| **813 字符** |
| ② | `app/EventBus.js@133` → `app/EventBus.js@1251` | 行注释 `` // `mount` 是给 `features/**` 认领的接口… `` 同理 | **1119 字符** |
| ③ | `core/materials/fill.frag.glsl.js` ×3 | **GLSL 模板串**里的 `/* ---- 一楼炉火 ---- */` / `/* ---- 二楼魔法吊灯 ---- */` / `/* ---- 室内点光源（…） ---- */` 是**着色器源码的注释**，被当成 JS 块注释剥掉 | 97 字符 |

**这正是"根治"相对"提示性检查"的额外收益**：不只是少算了注释，而是旧判据本身读到的文本就是**残缺的**。

**逐文件归因**：112 个文件中，块注释剥离有差异的只有 **1 个**
（`core/materials/fill.frag.glsl.js`：旧剥 340 / 新剥 243 字符）。其余差异全部来自**拼接文本**上的
跨文件误剥（① ②）—— 也就是说，**旧判据的 b 侧输入一直是错的**。
