## 2 · ★ 修订前的核查发现（原提案与实际不符）

§12.2 步 2 的价值在本次得到了实证——**核查纠正了原提案**：

| | 内容 |
|---|---|
| **原提案**（`J3.3` 收尾时给出） | 「从 §3⑥ 的手工动作里**删掉** `git tag -a task/<编号>` 这一步」 |
| **核查发现** | **SPEC-1.0.1 里根本没有这一步**。`J3.2` 重构时把手工动作从 §3⑥ 移到了 **§11.1「手工等价收尾」**，而那份代码块只包含 merge / tag `v<base>-dev.N` / 删分支，**不含** task tag |
| **实际病因** | 真正的不一致在 **§2.1 账本**：它登记了一个"**谁都不生产**"的命名空间——工具不产生（`task:done` 无此步）、手工路径也不产生（§11.1 无此步）。§3.6 却仍描述成"手工创建" |
| **修正后的方案** | 不是"删一步"，而是**废止该形态**：账本移除 + 冻结表说明孤例 + 生命周期表标废止 |

> **教训（值得记进方法）**：修订提案本身也可能是错的。
> **§12.2 步 2「影响面清单」的作用不只是评估影响，它强制你先去核实提案的前提是否成立。**
