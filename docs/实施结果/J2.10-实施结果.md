> （落点 `cabin/systems/weather/environment.js`）。
> 版本管理：[`VERSIONING.md`](../VERSIONING.md) §3。

## 1. 做了什么

环境量（天气 / 时间 / 采光）有了**唯一持有者**，并通过事件总线广播：

| 新增 | 内容 |
|---|---|
| `systems/weather/environment.js` | `createEnvironment({ bus, fillMaterial })`：`setWeather` / `applyDaylight` / `setGameHour` / `flush` / `snapshot` |

**接入 monolith 的 3 处**：

| 位置 | 改动 |
|---|---|
| `setWeather(t)` | 追加 `environment.setWeather(t)` —— 天气变化**立即广播** |
| `FILL.uniforms.uDaylight.value = dayFactor` | 改为 `environment.applyDaylight(dayFactor)` —— 采光的唯一入口 |
| `tickOnce()` 的帧末 | 追加 `environment.setGameHour(curHour()); environment.flush();` |

```js
bus.on('env:change', ({ weather, daylight, gameHour }) => { … })
```

## 2. 为什么必须解耦（不变量 `N1`）

搬迁前，想响应环境变化的代码**只能去读别人的变量**：
`wx.type`（天气系统的内部对象）、`FILL.uniforms.uDaylight`（材质 uniform）、`gameSec`（时间）。
于是 `core/` 与 `systems/` 里会出现具体物件的名字 —— 正是 `N1` 禁止的。

解耦后，`J3` 搬每件物件时只需在自己的 `update` 里订阅一次：

```js
// world/outdoor/fireflies.js（示意，J3 会这么写）
bus.on('env:change', ({ weather }) => { visible = weather === 'sunny' })
```

**这就是"新增一个模块不改核心"的另一半** —— 第一半是 `J2.6` 的注册式交互。

## 3. ★ 广播节流：太阳每帧都在走

`daylight` 每帧都在变（太阳在移动），但**每帧广播一次事件毫无意义** ——
订阅者做的是"亮度跨过某个阈值就换贴图"这类事。因此 `flush()` 只在：

| 条件 | 阈值 |
|---|---|
| 天气换了 | 立刻（离散量，不节流） |
| 采光变化 | > **1%** |
| 游戏内时间变化 | > **0.02 小时** |

才真正 `emit()`。没有变化时 `flush()` 返回 `null`（测试里断言了这一点）。

## 5. 新增测试：9 项（`tests/unit/environment.test.mjs`）

| 测试 | 守什么 |
|---|---|
| 天气变化立刻广播；设成同一个天气不算变化 | 离散量的语义 |
| 采光累计 0.5% 抖动不广播、跨过 1% 才广播 | **节流**（否则每帧一次事件） |
| 没有新变化时 `flush()` 返回 `null` | 调用方可以据此做别的事 |
| `applyDaylight` 是写 `uDaylight` 的唯一入口 | 不会出现"某处直接改 uniform、环境量却不知道" |
| 没有 `fillMaterial` 时不报错 | 单元测试与无材质场景 |
| 时间跨过 0.02 小时也会广播 | "天黑了"这类判断靠它 |
| `snapshot()` 与广播出去的对象同构 | 订阅者拿到 `weather/daylight/gameHour` |
| 环境量是**纯数据**（可序列化） | 不该夹带 `THREE.Color`/`Vector3` |
| 缺少 `bus` 时报错 | 契约 |

## 7. 遗留与交接

| 项 | 留给谁 | 说明 |
|---|---|---|
| 现有物件**订阅** `env:change` | `J3` | 现在已有订阅方（暂无）；`J3` 搬窗户玻璃 / 星空 / 萤火虫时接上 |
| 天气系统整体搬迁 | `J4` | `sky.js` / `precip.js` / `clouds.js` / `stars.js` / `WeatherSystem.js` 仍是 monolith 内的函数；`environment.js` 是它们的"状态出口" |
| `uDaylight` 之外的落地处（`scene.background` / `fog`） | `J4` | 现在仍由天气系统直接改；`environment` 只统一了采光这一处 |

## 8. 一句话总结

**环境量从"散在天气系统内部、别人直接读"变成"一个持有者 + 一条广播"** ——
它本身只有 100 多行，但它是 `J3` 里每件物件"自己订阅环境、而不是被核心点名"的前提；
节流那一条则保证了解耦不会变成"每帧一次事件风暴"。
