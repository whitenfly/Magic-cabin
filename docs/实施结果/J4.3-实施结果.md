### 1.1 ★ 三个静默失配（全部通过 `tsc` + `build`，只被页面拦下）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| **①** | `ReferenceError: bus is not defined` | `createEnvironment({ bus, fillMaterial: … })` 是**简写属性**。`getSymbolAtLocation(简写属性的 name)` 返回**节点自身**的属性符号 ⇒ `declarations[0]` 落在段内 ⇒ 既不进 `appUsed` 也不进 `unknown`，**静默漏掉** | 统一走 `checker.getShorthandAssignmentValueSymbol()` |
| **②** | `ReferenceError: createEnvironment is not defined`（`THREE` / `createLightField` / `createPointLightSource` 同样） | 我为了给 `resolveTopDecl` 加兜底，在 `symbolOf()` 里做了 `getAliasedSymbol()` —— 它把 import 符号解析成**目标模块里的**符号，`declarations[0]` 于是变成 `environment.js` 里的 `FunctionDeclaration`，`isImportSym` 判据失配 ⇒ **5 条 import 一条都没补上**，而且不报 `unknown`（符号解析成功了，只是落在别的文件） | `symbolOf()` **不做** alias 解析（调用方要看"这就是 import 符号"，必须看原始 alias 符号）；alias 兜底只留在 `resolveTopDecl()` 里 |
| **③** | 13 个参数名（`t` / `el` / `i` / `dt` / `time` / `m` …）被误报成"搬出去没人给" | 新加的防御判据「符号的声明位置 == 引用位置 ⇒ 解析失败」把**参数名节点**也算进去了（形参本身会被遍历到），而 `skip` 列表里**漏了 `Parameter`** | `skip` 补 `ts.isParameter(p) && p.name === node` |

**①和②是同一个坑的第三、四次复发** —— 所以这次把"符号怎么解析"抽成**唯一入口** `symbolOf()`，
并在注释里写明"凡是按符号找声明的地方，一律经这个函数"。

### 1.2 新增的防御判据

```js
// 符号的声明位置**就是引用位置本身** ⇒ 符号解析失败（简写属性的典型症状）。
// 它既不会进 appUsed、也不会进 unknown，会**静默漏掉** —— 所以必须显式报出来。
if (d && d.getStart(sf) === node.getStart(sf)) {
  unknown.add(`${node.text}（符号指向自身 ⇒ 解析失败）`)
  return
}
```

> 这条判据**立刻**报出了 13 个误报（`③`）—— 也就是说，它本身是对的，是我的 `skip` 列表不全。
> 判据能报错，说明它有分辨力；把误报修掉之后它就是**"解析失败"这件事本身**的守门人。

## 6. 结论

`J4.3` 的交付面是一段 583 行的系统，但它真正的产出是**三条判据的修正**：

- `symbolOf()` 成为"符号 → 声明"的**唯一入口**（简写属性 + alias 解析这两个坑都在它里面被堵死）；
- `importByName` 按名字而不是按偏移索引（namespace import 的 `getStart()` 指向 `*`）；
- "符号指向自身 ⇒ 解析失败"成为一条**显式判据**，而不是靠人工 review。

三次静默失配有一个共同特征：**`tsc` 与 `build` 全程零错误**。
这正是 [`VERSIONING-QA.md`](../VERSIONING-QA.md) 反复强调的那条 ——
**判据必须表达问题本身**，否则它只是问题的影子。
