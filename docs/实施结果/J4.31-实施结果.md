# J4.31 · 提取共享数学/几何工具（`smooth` / `hash01` / `jitterGeo`）—— 实施结果

> 编号 **`J4.31`** ｜ 分支 `task/J4.31-shared-math-tools` ｜ `--base=0.4.0`
>
> **这不是"搬物件"，而是"提取共享工具"** —— `floor2/wand` 与 `floor2/board` 的**共同前置**。
> 两份 SKIP 各自把它列为前置第 1/2 条，并明确写："**这一步同时解锁 18.8 与 18.9**"。

## 0. 一句话结论

把三个**长在分区区间里、却被别处依赖**的工具提取到 `core/`：

| 工具 | 原定义位置（区间内） | 现在住在哪 |
|---|---|---|
| `smooth(k)` | **18.8 计划板**段内（`const smooth = k => k * k * (3 - 2 * k);`） | `core/math/easing.js` |
| `hash01(s)` | **18.9 魔法杖**段内 | `core/geometry/jitter.js` |
| `jitterGeo(geo, amp)` | **18.9 魔法杖**段内（内部用 `hash01`） | 同上 |

并由 `propCtx` 直接注入（不再 `() => ctx.smooth` 那样"从某个物件的段导出里取"）。

画面 **3/3 机位 sha256 逐字节相同**；页面诊断 0 错误。

## 1. 为什么必须提取（两份 SKIP 记的**同一笔债**）

### 1.1 `smooth`：18.8 一动，18.9 就崩

`floor2-board.SKIP.md` §2① 与 `floor2-wand.SKIP.md` §2② 记的是同一件事：

- `smooth` 住在 **18.8（计划板）** 的区间里；
- **18.9（魔法杖）** 的每帧分支 `updateWand2` 用了它 **3 处**（起飞 / 生长 / 归位三段缓动）。

⇒ 18.8 一搬，18.9 立刻 `ReferenceError`；18.9 也搬不动（拿不到 `smooth`）。
`wand` 的 SKIP 写得直白：「**先把 `smooth` 提取出去，18.8 与 18.9 会同时解锁**」。

### 1.2 `hash01` / `jitterGeo`：它们是 `ctx` 共享工具，定义却在 18.9 里

`floor2-wand.SKIP.md` §2①：

> `propCtx` 里 `propTool('jitterGeo', …)` / `propTool('hash01', …)` 指的就是这两个函数；
> `floor2/junkBoxes.js` 的兄弟件 `crumpleBall`（18.10 段）也在调 `jitterGeo(...)`。
> 区间一删，`ctx.jitterGeo` / `ctx.hash01` 双双 `ReferenceError` ——
> **凡是 `build` 里解构了它们的已搬物件都会在装配时炸**。

⇒ 这两个**必须**与 18.9 的几何段一起搬（或先提取），否则搬 `wand` 会连带炸掉已搬的 `junkBoxes`。

### 1.3 还有一份"复刻"在等着被删

`floor2/junkBoxes.js` 的 `update` 里有一行
`const smooth = k => k * k * (3 - 2 * k);   /* 复刻 monolith IIFE 里的同名缓动 */`
—— 那是 `J3` 时代因为拿不到 `smooth` 而**复制的实现**。提取之后它就该消失。

## 2. 做了什么（2 个新文件 + 4 处改动）

| 文件 | 动作 |
|---|---|
| `core/math/easing.js` | **新增**：`export const smooth = k => k * k * (3 - 2 * k)`（**逐字**） |
| `core/geometry/jitter.js` | **新增**：`hash01` + `jitterGeo`（**逐字**，见 §2.2） |
| `app/scene/PropInstaller.js` | 两行 `propTool` 改为**指向 `core/` 的实现**（`() => jitterGeo` / `() => hash01` / `() => smooth`）+ 2 条 import |
| `world/floor2/install.js` | 删 `const smooth = …` 与 `ctx.smooth`；删 `hash01` / `jitterGeo` 两个函数定义；**删** `ctx.hash01` / `ctx.jitterGeo` 两个段导出分句（§2.3）；顶部 import 三个同名符号 |
| `world/floor2/junkBoxes.js` | 从装配环境解构 `smooth`，**删掉那份复刻** |

**段内调用一字未改**：因为 import 进来的名字与原局部名**相同**（`smooth` / `hash01` / `jitterGeo`），
`install.js` 里所有使用点（18.8 的 `glyphLocalX` 一带、18.9 的 `buildMagicCircle` / `buildCreation`）
与 `junkBoxes.js` 的 `update` **一个字符都没动**。

### 2.1 `smooth` 的定义被**搬走**而不是"再写一份"

原文 `const smooth = k => k * k * (3 - 2 * k);` 与 `core/math/easing.js` 里的**逐字相同**。
`install.js` 现在从 `core/math/easing.js` import 它 —— **不存在第二份实现**。

### 2.2 ⚠️ `hash01` / `jitterGeo` 是"一个字符都不能改"的典型

`wand` 的 SKIP 特别提醒过：

> `jitterGeo` 内部就用 `hash01`，两者要一起搬，且必须**逐字**搬运
> （它对顶点做的是 `toFixed(3)` 字符串哈希，**改一个字符画面就变**）。

本任务照办：哈希用 `h * 31 + charCodeAt(i) % 997`、抖动用 `toFixed(3)` 拼出的**字符串**
（含逗号与 `'x'`/`'y'`/`'z'` 后缀）做键 —— **一字未改**。
`core/geometry/jitter.js` 的文件头把这条约束写成了模块级警告。

### 2.3 段导出的悬空引用（**第五次**同类，主动拦下）

`install.js` 的段导出里有 `ctx.hash01 = hash01; ctx.jitterGeo = jitterGeo;` ——
靠**函数声明提升**引用本段局部函数。两个函数提取走之后，该分句会在装配期抛 `ReferenceError`。

处理：全局搜索确认 `ctx.hash01` / `ctx.jitterGeo` **没有任何读者**
（`propCtx` 的 `propTool` 已改为直接指向 `core/`），删除这两个分句。

> 前四次：`J4.20` 的 `startQuill` · `J4.26` 的 `makeCup` · `J4.28` 的 `makeCushion` ·
> `J4.30` 的 `clockHand`/`drawClock`。这是**第五次**——「搬/提取前先查段导出清单」
> 这个动作已经连续五次拦下同类故障。

### 6.1 ★ 本任务解锁了什么

`floor2/wand` 与 `floor2/board` 的**共同前置已就绪**：

| 件 | 还缺什么 |
|---|---|
| **`floor2/wand`**（18.9，约 600 行，二楼最大） | ✅ `hash01`/`jitterGeo` 已提取 · ✅ `smooth` 已提取 · 其余：`clock.now` → `s.now`（`rubik` 同法）、`runtimeRng` 次数与顺序、`scene.add/remove` 的动态增删顺序（`wand` SKIP §3 已逐条列出） |
| **`floor2/board`**（18.8，5 件 + 便签编辑器） | ✅ `smooth` 已提取 · 其余：便签编辑器的归属（应由 `features/**` 经 `mounts` 认领 `parts`，见 `decor-loop.SKIP.md` §3 —— `J4.27` §2.1 已把它划归本组） |

> ⚠️ 两者都**还没到"可以无脑开搬"**：`wand` 有 `scene.add/remove` 的动态增删顺序问题，
