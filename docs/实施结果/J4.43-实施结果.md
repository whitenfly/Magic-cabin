## 2. ★ 编辑器归位（`J4.42` §2 的裁决落地）

### 2.1 做了什么

| 动作 | 位置 |
|---|---|
| `applyNote()` + `#noteOk` 的 click 监听 + `#noteInput` 的 keydown 监听 | **搬进 `board.js` 的 `build` 闭包** |
| **删除 `src/cabin/systems/ui/editors/NoteEditor.js`** | 该目录现已为空 |
| 去掉 `installCabin.js` 的 `import { installNoteEditor } …`（原 L45） | ✅ |
| 去掉 `installCabin.js` 的 `installNoteEditor(ctx, app)` 调用（原 L78）| ✅，段序注释同步改写 |

依据：`floor2/picture.js`（`J3` 升格）面对同一问题时的处置就是
「编辑器函数 + DOM 监听**全在模块内**，只经 `state` 暴露给 `interactables`」。

### 2.2 ⚠️ 唯一保留的跨层豁免：`ctx.noteInput`

`ctx.noteInput` 有两个**系统层**读者（`Input.js` L24 · `PlayerController.js` L20，
作用都是"在输入框里打字时吞掉游戏快捷键"）。按施工图 §2.4 的方案 **(a)**：

```js
const boardApi = ctx.installProp(board);
ctx.boardApi = boardApi;
ctx.noteInput = boardApi.parts.noteInput;   // ★ 装配层显式写回（不是物件内部伸手）
```

> ⚠️ **不能在 `board.js` 的 `build` 里写 `ctx.noteInput = …`** —— `propCtx` 的属性是
> **只读 getter**（`PropInstaller.js` 用 `Object.defineProperty(propCtx, name, { get })`，无 setter），
> 而 ES module 是严格模式 ⇒ 赋值会**直接抛 `TypeError`**。
> 必须经 `parts` 走到**装配层**赋值 —— 这一点已写进 `board.js` 文件头与 `install.js` 的注释。

**更干净的"统一输入框判据"记为后续改进项**（会改变行为，需单独任务 + 实测）。

## 3. ★ `rng`：1020 次 `textureRng()`（不变量 `N8`）

`drawBoardFace()` 的 `for (i < 340)` 循环内 **3 次** `textureRng()`
⇒ **340 × 3 = 1020 次**，**全项目单件最多**（多于 `star-particles` 的 672 次 `floor2Rng`）。
该函数只在 `build` 期调用一次 ⇒ **装配位置留在原位**，本件从装配环境取 `rng.texture`
（与 `install.js` 顶部的 `const textureRng = scene.texture` 同一实例）。

**⇒ `visual` 3/3 逐字节相同即证明这 1020 次序列未错位。**

## 4. ★ 三条相邻的帧任务合并（判据 ①，天然等价）

| 原帧任务 | 内容 |
|---|---|
| `frame/55` | `eraserT += ((eraserOpen ? 1 : 0) − eraserT) × 0.06` |
| `frame/56` | `eraserG.rotation.x = π · eraserT²(3 − 2·eraserT)` |
| `frame/57` | `updateChalk(time)` |

三条**连续**（前后分别是 `frame/54` 枕头、`frame/58` `updateWand2`，都不属本件）
⇒ 合并成一个 `update`、登记在 `frame/55` 的位置、内部顺序不变
—— 这是判据 ①（相邻），**无需**论证"中间任务无读者/写者"
（对照 `J4.36` 隔 1 个、`J4.39` 隔 35 个）。

### 4.1 `updateChalk` 的组织方式

`updateChalk` 需要 `drawGlyphSet`（闭包内）、`GLYPHS`、`glyphLocalX,Y`、`CHALK_HOME` 与 `smooth`
⇒ 它**留在 `build` 闭包内**定义，经 `parts.updateChalk` 交给 `update` 调用
（**不**把 `drawGlyphSet` 等再导出一次，避免二次提升与状态分裂）。

### 4.2 `clock.now` → `s.now`

原 `chalkState.start = clock.now` 改为 `s.chalkStart = s.now`（`update` 第一行写 `s.now = time`）——
与 `rubik` / `magicBook` 同法（点击事件在两帧之间执行 ⇒ 与 `clock.now` 恒等）。

## 5. ★ `build` 能拿到 `state`（本件用到的一条既有机制）

本件在 `build` 内需要读写物件自己的 state（`openNoteEditor` 写 `s.noteEditing`、
`applyNote` 读它、`updateChalk` 读写 `s.chalkActive/chalkStart`）。
**`installProp` 在调 `build` 之前就把 state 实例写进了 env**
（`app/installProp.js` L96–97：`const state = prop.state(env); env.state = state`）
⇒ `build({ …, state: s })` 合法，`floor2/coinTowers.js` 早已如此。

> 这条机制在施工图里没有写明，是本件实施时查证的 —— 已记入本文档，供后续复用。

## 8. ★ 门禁期间修掉的两处计数污染（`verify-migration.mjs`）

本件第一次跑 `_verify` 时 `verify-migration.mjs` 报**两项红**，都属于同一类老坑
（该脚本的 `stripComments` **只剥块注释、不剥行注释**），必须如实记录：

| 项 | 现象 | 根因 | 处置 |
|---|---|---|---|
| `Math.random()` | `286 → 287`（**+1**）| 我在 `install.js` 的**行注释**里写了 `textureRng()` 字面量 —— 该脚本会把 `textureRng()` **反向还原**成 `Math.random()` 再计数 | 注释里去掉括号 ✅（★ 连"解释这个坑的注释"本身也得遵守这条 —— 第一次修的时候我又写了一次带括号的，遂再修）|
| `regMagic(` | 白名单 −32，实测 **−35** | 本件真实删掉 **5** 处调用；但 18.8 段的**行注释里原有 2 处**「函数名 + 左括号」字面量，随整段一起被删除 ⇒ 文本计数额外 −2 | 白名单 −32 → **−35**，并在脚本里写明分解 ✅ |

> 这类"注释字面量污染计数"在本项目已出现 **8 次**（`J4.19`/`J4.21`/`J4.36`/`J4.39`/`J4.41`/本件…），
> 且**首次出现"因删注释而负向偏移"**。根因是 `stripComments` 不剥行注释 ——
> 脚本自己也在 L250–256 解释了"两边用同一套剥离规则"，但行注释仍在规则之外。
