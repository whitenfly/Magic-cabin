## 2. ★ 裁决：便签编辑器归谁

### 2.1 现状（`J4.32` §3.3 记的那个待裁决点）

`systems/ui/editors/NoteEditor.js`（39 行）的 `applyNote()` 直接读计划板的**私有量**：

```js
ctx.notes[ctx.noteEditing].txt = noteInput.value.trim() || '...';
ctx.drawNote(ctx.noteEditing);
```

⇒ 这是**系统层反向伸手进物件**。`J4.32` §3.3 指出应由 `features/**` 经 `mounts` 认领 `parts`（`N3`）。

### 2.2 ★ 既有先例：`floor2/picture.js` 已经这么做了

`picture.js`（`J3` 升格）面对**同一个问题**（它也有 DOM 编辑器），它的处置是：

| 做法 | `picture.js` 的代码 |
|---|---|
| 编辑器函数**留在物件内** | `function openPicEditor() { … }` / `function applyPic() { … }` 都在模块里 |
| **DOM 监听器也留在物件内** | `document.getElementById('picOk').addEventListener('click', applyPic);` + `keydown` 监听 |
| 经 `state` 暴露给 `interactables` | `state.openPicEditor = openPicEditor;` → `onActivate: () => { s.openPicEditor(); }` |

⇒ **`NoteEditor.js` 是 `J4` 段切片的产物（段 11），`picture.js` 是更晚、更正确的形态。**

### 2.3 裁决内容

1. 把 `NoteEditor.js` 的 `applyNote()` 与两个 DOM 监听（`#noteOk` 的 click、`#noteInput` 的 keydown）
   **搬进 `board.js` 的 `build` 闭包**；
2. **删除 `src/cabin/systems/ui/editors/NoteEditor.js`**；
3. 去掉 `installCabin.js` 的 `import { installNoteEditor } …` 与 `installNoteEditor(ctx, app)` 调用
   （L45 / L78）；
4. `ctx.applyNote` / `ctx.noteEditor` 两个导出随之消失（**已 grep 确认无外部读者**）；
5. `scripts/oneoff/_j4-segments.mjs` 的段表（L114）是**一次性调研工具**、不参与门禁
   ⇒ 可在提交信息里说明，不必改。

### 2.4 ⚠️ 一处必须保留的跨层豁免：`ctx.noteInput`

`ctx.noteInput` 有**两个系统层读者**（**这是本件唯一真正的跨层耦合**）：

| 读者 | 用途 |
|---|---|
| `systems/player/Input.js` L24 | `if (document.activeElement === signInput \|\| … === ctx.noteInput \|\| … === picInput) return;` —— 在输入框里打字时**不要触发游戏快捷键** |
| `systems/player/PlayerController.js` L20 | 同上，判断"是否正在输入"来决定是否响应移动 |

**两个候选**：

| 方案 | 说明 | 评价 |
|---|---|---|
| **(a) 保留 `ctx.noteInput`** | `board.js` 的 `build` 里写一行 `ctx.noteInput = noteInput;`（**显式、带注释的豁免**）| ✅ **推荐** —— 零行为风险，与 `ctx.signInput` / `ctx.picInput` 现状一致 |
| (b) 改判据 | 两个系统层改为"`document.activeElement` 是 INPUT/TEXTAREA 就吞掉按键"，不再逐个列举物件的输入框 | ⚠️ **更干净，但会改变行为**（任何新输入框都会生效）⇒ 需单独任务 + 实测，**不在本件范围** |

⇒ **本件取 (a)**，并把 (b) 记入 `J4.32` §5 的遗留清单。

> ★ **`J4.51`（R4b）已把 (b) 做掉**：两个系统层改为共用统一判据 `ctx.isTypingTarget()`
> （焦点在 `INPUT`/`TEXTAREA`/`contentEditable` 上就吞按键），本件留下的那处**唯一跨层豁免**
> （`install.js` 的 `ctx.noteInput = boardApi.parts.noteInput;` 与 `board.js` 的 `parts.noteInput`）
> **已删除**。§109 预判的"会改变行为"也被实测确认并**写成了断言**：
> 设置面板的 range 滑块从此也会吞按键（它拖完不 blur）——详见 `J4.51-实施结果.md` §2。判据 `pnpm test:input`。
