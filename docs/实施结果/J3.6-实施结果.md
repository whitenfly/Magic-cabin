## 2 · 删除动作与无损验证（实测）

**执行**（R10：变更类命令必须走 `exec` 入口，自动写入 `GitPushHistory.md`）：

```bash
node scripts/release.mjs exec -- git tag -d task/J3
# → Deleted tag 'task/J3' (was e1259c3)
```

**删除前的核查**（用户提"是否有不好的影响"时做的四维度验证）：

对 `task/J3` 指向的提交 `f00bf11` 执行 `git for-each-ref --points-at`：

```
task/J3         [tag]
v0.3.0-dev.1    [tag]      ← ★ 同一提交还有第二个 tag 守着
```

**删除后逐项验证**：

| # | 验证项 | 命令 | 结果 |
|---|---|---|---|
| 1 | tag 已删净 | `git tag -l "task/*"` | ✅ 空 |
| 2 | **提交仍被引用** | `git for-each-ref --points-at f00bf11` | ✅ 仍列出 `v0.3.0-dev.1` |
| 3 | **可达性不依赖 tag** | `git merge-base --is-ancestor f00bf11 dev` | ✅ `exit=0`（是 `dev` 祖先） |
| 4 | 提交信息未丢 | `git log -1 --format=%s f00bf11` | ✅ `J3 收尾：结果文档数字对齐（35/67 件）+ 阶段状态同步` |
| 5 | `git describe` 未受影响 | `git describe --tags` | ✅ 仍为 `v0.3.0-dev.5` |
| 6 | 回退能力未丢 | `git switch --detach v0.3.0-dev.1` | ✅ 仍可回到那一刻（该 tag 就是快照） |

> **无损的根据（三重）**：① 同一提交有 `v0.3.0-dev.1` 这个**版本快照** tag；② 它是 `dev` 的祖先，**可达性根本不依赖任何 tag**；③ 提交信息自带 `J3 收尾：…`。
> 加上第 4 点前提：**它从未推送**（`ship` 只收 `v*`，远端不存在）⇒ 删除**不影响任何克隆方**。
