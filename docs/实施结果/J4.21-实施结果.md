## 1. 病根（`J3` 记的硬阻塞）

`floor2-desk-chair.SKIP.md`：

```js
{ g: chairG, hx: 0.24, hz: 0.24, top: FY + 0.49, bot: FY },   // movingPlatforms
```

椅子**沿 z 平移**，碰撞盒必须跟着走（`refreshPlatforms()` 每帧读 `m.g.position.x/z`），
所以那一行不能删。搬走几何段 = `chairG` 消失 ⇒ 每帧 `ReferenceError`（**直接崩**）。

`J3` 记的额外麻烦：`tickOnce()` 里椅子那三行**混在九行里**（椅子 / 枕头 / 黑板擦三个物件），
而 `spec.tick` 当时只能声明**一处**替换 —— 现在 `J4` 已经是模块化代码，不存在这个问题。

### 4.1 ⚠️ 预期红：`cabin-digest`

### 4.2 ★ `regMagic(` 计数白名单 `-21` → `-22`，以及**同一个判据缺陷又踩了两次**

`floor2/install.js` 里删掉 **1** 处 regMagic 调用 ⇒ 计数应 −1。

**实测却纹丝不动**（`64 → 43`，期望 −21 正好等于当时的白名单）。原因：新模块的行注释里
写出了那个「函数名 + 左括号」的字面量 —— 而 `verify-migration.mjs` 的 `stripComments()`
**只剥块注释、不剥行注释**（这条缺陷已记在 `J4.20` §4.2）。

**更好笑的是**：改掉之后，我在**解释这件事的注释里**又写了一次同样的字面量
⇒ 计数**第二次**被抵平。第三版改用"那个「函数名 + 左括号」的字面量"的措辞之后，
才真正变成 `64 → 42`（−22），白名单随之更新。

> ⇒ 这条缺陷**已经足以影响结论**（不是理论问题）：
> **"删掉 1 处代码 + 写 1 行解释注释"= 判据上看不见搬迁。**
> 本轮仍**不根治**（改 `stripComments` 会牵动另外 7 个计数的期望值），
> 但已把两次实证写进 `verify-migration.mjs` 的注释里，供后续任务判断。
> **判据强度不变**：它守的仍是"有没有人**偷偷加** regMagic"（那会让计数上升，当场变红）。

## 6. 遗留与交接

### 6.1 ★ 顺序调整：为什么先做 `desk-chair` 而不是 `teapot`

`teapot` 组（提梁茶壶 + 12.9f 余段茶杯/椅子）有**硬依赖**，`SKIP` 写得很清楚：

- 茶壶读 `const CUP_T = cups[2]`，而 `cups` / `makeCup` 也被 **12.13 暖桌**读
  （`makeCup(-0.34, -0.34, KTOP, kotatsuG)`）⇒ 搬茶壶必须先解决"共享茶杯工厂"；
- `_tv`（临时向量）被茶壶**与暖桌收音机**共用（`src.getWorldPosition(_tv)`）
  ⇒ 茶壶一搬走，暖桌那 5 行立刻 `ReferenceError`。

**⇒ `teapot` 组的前置是暖桌（`floor1/kotatsu`），而暖桌属批 2。**
`J4.18` 已经把暖桌的光源槽位问题解决（`slot: 3` + `lights()` 通路），
所以正确顺序是：**先做 `cups` 共享件 + 暖桌，再回来做 `teapot` 组**。
本任务因此先取独立性最强的 `desk-chair`（`SKIP` §3 已给现成配方）。

### 6.2 其它

1. **`chairs` 仍被 `movingPlatforms` 读**（`...ctx.chairs.map(...)`），
   它是 `teapot` 组那 5 把椅子的数组 —— 与 `chairG` 同款，搬那组时一并处置。
2. **动态行为无独立判据**（§3 的边界说明）。若后续要补，可参照 `tests/e2e/cart-shelf.mjs`
   的模式（对准 → 真实点击 → 推帧 → 与"不点击"的对照比像素）。
3. **`verify-migration.mjs` 的 `stripComments` 缺陷**（§4.2）—— 两次实证，建议根治。
