## 0. 一句话结论

月光魔法盆栽升格为 `world/floor1/moonPlant.js`：几何 + 1 条交互 + 两段合并的 `update`
+ **`lights()` 声明的槽位 7**。`J3` 记的**两条走不通的路**同样都被解开：

| `J3` 记的走不通的路 | `J4.23` 之后 |
|---|---|
| 把光源写进 `lights()` ⇒ 会在**盆栽所在位置**注册 ⇒ 盆栽变槽位 0、其余 7 盏相位全移位 ⇒ 画面必变 | ✅ `slot: 7` **显式声明**槽位 —— 在哪一段注册都落在第 7 槽 |
| 保留 `plantRun` 在 monolith ⇒ 违反 `N7`，交互也得留着 ⇒ 等于没搬 | ✅ `s.run` / `s.pt` 是物件私有 state，`strength` 闭包直接读它 |

画面 **3/3 机位逐字节相同**。

## 1. 病根

```js
// 光源注册（槽 7，world/lights.js）：读的是 ptPlant，不是 plantRun
strength: () => ptPlant
// 区间外赋值（tickOnce() 的「室内点光源」段）：
ptPlant += ((plantRun > 0 ? 1 : 0) - ptPlant) * 0.055;
```

`plantRun` 随几何段搬走之后，那一行会 `ReferenceError`（整个 `tickOnce` 当场停摆）。

### 2.1 帧顺序：`ptPlant` 的平滑提前，为什么等价

一件物件只有一个 `update`：几何分支在 `frame/26`、强度平滑在 `frame/96`
（`lightField.update` 是 `frame/97`）⇒ 本件选**几何分支的位置**（早）。论证与 `hangingLantern.js` 同款：

1. **数值序列完全相同**：一阶低通，同帧同 `dt` 同输入 ⇒ 逐位相同；`grep plantRun` 的全部命中
   只有本物件（外加 `frame/97` 才被调用的 `lights()` 闭包）⇒ **两位置之间没有任何读者或写者**；
2. **仍然早于读者**：本 `update` 在 `frame/26` 位置，远早于 `frame/97`。

> ⚠️ `J4.22` §6.1 提醒过「每件都要单独核对这个方向」—— 本件核对通过（无中间写者）。
