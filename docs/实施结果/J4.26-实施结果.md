> 编号 **`J4.26`** ｜ 分支 `task/J4.26-cup-shared-factory` ｜ `--base=0.4.0`
>
> **这不是"搬物件"，而是"抽共享件"** —— `J3` 为 `floor1/kotatsu`（暖桌）留下的**两条前置之一**。
> 完成它之后，**暖桌与提梁茶壶才可能搬**。

## 0. 一句话结论

把 `makeCup`（茶杯工厂）与那段"茶杯升腾 / 水汽"的每帧分支从 `floor1/install.js` /
`FrameBody.js` 抽成 `src/cabin/props/cup.js`，导出 **`createCupFactory(deps)`**：
`cups` 集合住在**闭包**里（不是模块级单例 ⇒ 不违反不变量 `N7`），
`makeCup` 成为**任何物件都能 import 的共享工厂**。

画面 **3/3 机位逐字节相同**；`regMagic(` 调用点计数**净变化为 0**（交互没消失，只是跟着工厂搬了家）。

## 1. 为什么需要它（`J3` 记的"阻塞二"）

`floor1-kotatsu.SKIP.md` §「阻塞二」：

```
makeCup 定义在上一个分区（/* 茶杯（餐桌/暖桌通用） */），cups 数组同时被三处读：
  · 提梁茶壶   const CUP_T = cups[2];                 ← 茶壶往哪只杯子倒水由它决定
  · 暖桌       makeCup(-0.34, -0.34, KTOP, kotatsuG); ← 桌上摆两只茶杯
  · 每帧       for (const c of cups)                  ← 茶杯升腾 / 水汽动画
⇒ 暖桌与茶壶都依赖长餐桌那一件的内部函数 …
  得先把 makeCup 抽成 cabin/props/ 级别的共享工厂
  （world/README.md 已经写了这个方向：「跨场景复用道具放在 cabin/props/，本目录只负责摆放」）
```

本任务就是那件事。**摆放仍由各物件自己声明**（谁放几只、放在哪，仍写在各自的装配点里）。

### 2.1 为什么是「工厂」而不是「模块级单例」

`cups` 是**跨物件的共享集合**（长餐桌 3 只 + 暖桌 2 只 = 5 只），每帧动画要遍历它。
但它**不能**做成模块级单例 —— 那会引入**全局可变状态**（违反不变量 `N7`：
"物件状态活在闭包（`state()`）里"）。故导出 `createCupFactory(deps)`：集合住在闭包里，
由装配点在**原位置**创建一次，再把 `cups` 交给需要它的读者
（与 `J4.18` 的 `LightField`、`J4.20` 的 `parts.consts` 同一思路）。

### 2.2 ★ 又一处「未定义的自由变量」——这次是**主动**发现的

`install.js` 开头有一行 J4 段切片留下的跨段导出，它靠**函数声明提升**引用本段的局部函数：

```js
ctx.makeCup = makeCup; ctx.makeChair = makeChair; ctx.makeCushion = makeCushion;
```

`makeCup` 一旦搬走，这一分句会立刻 `ReferenceError`（整个装配段停摆）——
**与 `J4.20` 的 `ctx.startQuill = startQuill` 完全同款**。
全局搜索确认 `ctx.makeCup` **没有任何读者**，故删除该分句（保留另两个，
它们仍由本段暖桌部分定义、且同样无读者）。

> 这是本任务**主动**做的检查（不是等页面报错）—— 因为 `J4.20` 已经踩过一次，
> 教训写进了那个任务的 §3.2。

### 2.3 ⚠️ 顺带发现：**PowerShell 的 `**` 通配不可靠**

本任务用 `Select-String -Path src/cabin/**/*.js -Pattern "ctx\.makeCup|…"` 做引用检查时
**返回空结果**，而改用 ripgrep（`grep` 工具）后命中 `install.js` L44 —— 即 `**` 在该
PowerShell 下**没有递归到深层目录**。

**⇒ 此后所有"引用/悬空变量"检查一律用 `grep` 工具，不用 PowerShell 通配**。

**对既有结论的影响（已复核，结论不变）**：`J4.19`–`J4.25` 那几次 PowerShell 引用检查
**可能**漏过深层文件，但那几个任务的**页面诊断都是 0 错误** ——
"未定义的自由变量"在装配期/首帧就会抛 `ReferenceError`，页面根本到不了 `ready`
（`J4.20` §3.2 正是这么暴露的）。**⇒ 结论由更强的证据守着，不受这条工具坑影响。**

## 6. 遗留与交接

### 6.1 ★ 本任务解锁了什么

`floor1/kotatsu`（暖桌）的两条前置现在**都已就绪**：

1. ✅ **光源强度进契约** —— `J4.18`（`slot: 3` + `lights()` 通路）；
2. ✅ **`makeCup` 共享工厂** —— 本任务。

⇒ **下一件可以直接搬暖桌**（`floor1-kotatsu.SKIP.md` §「下一轮」的条件 1、2 都满足了）。
搬完暖桌，`floor1/teapot` 组（提梁茶壶 + 12.9f 余段）也就解锁了 ——
它读的 `cups[2]` 与暖桌读的是**同一个共享集合**。

### 6.2 `ctx.cups` 暂时无读者

`FrameBody` 已改用 `cupFactory.update`，所以 `ctx.cups` 现在**没有读者**。
保留它是有意的：它是**共享集合的公开入口**，搬暖桌/茶壶时（那两件需要 `cups`）
正好用它 —— 那时应按 `J4.18`/本任务的思路，把它经 `parts` 或 `ctx` 显式交给物件。

### 6.3 其它

- **`verify-migration.mjs` 的 `stripComments` 缺陷** 仍在（5 次实证机会，本次没踩）。
- **`world/README.md`** 写的"跨场景复用道具放在 `cabin/props/`"方向，本任务落地了**第一个**实例。
