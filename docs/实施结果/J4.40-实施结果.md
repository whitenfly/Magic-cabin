## 1. 本件的特殊性：一个"没有交互"的物件

`defineProp` 的全部字段都是可选的（除 `id` / `build`）。本件刻意**不声明 `interactables()`**：

| 原实现 | 情况 |
|---|---|
| 18.6 段的 `regMagic` | **没有** —— 夜幕不是可点的陈设，它随星象仪的开关一起明暗 |
| 18.6 段的状态量 | **没有** —— 唯一的驱动量 `magicP` 属于 `astro` |
| `FrameBody` 的帧任务 | **只有 1 条**（`frame/73`）|

⇒ 这是"一件物件 = 一个文件"契约里**最简的一档**：
`build`（几何）+ `lights`（槽 6）+ `update`（1 行），没有 `state` 的实质内容、没有交互。

---

## 2. 依赖注入：本件**不需要**回填容器（与 `candle` 的对照）

`frame/73` 读 `magicP`（owner = `astro`）。两件的处置**不同**，原因是装配次序：

| 件 | 装配段 | 与 `astro`（18.5）的先后 | 处置 |
|---|---|---|---|
| `floor2/candle`（`J4.39`） | **18.3** | **早于** astro | 可变引用容器 `astroRef = { api: null }` + 在 18.5 之后回填 |
| **本件** | **18.6** | **晚于** astro | ★ **直接注入 `astroApi` 即可** |

```js
const astroApi = ctx.installProp(astro);                              // 18.5
ctx.magicVeilApi = ctx.installProp(magicVeil, { ctx: { astroApi } }); // 18.6（本件）
```

> ⇒ **教训（已写进 `J4.39` §2.1，此处是它的正面印证）**：判断"能不能直接注入"的唯一依据是
> **装配次序**，不是"依赖了谁"。早装配的件才需要容器。

## 4. ★ 批 2 收尾：`lights.js` 清空

本件把**最后一行** `lightField.register(…)` 收进了自己的 `lights()`：

```js
lights: (s, { L, astroApi }) => [
  createPointLightSource({
    id: 'floor2/magic-veil', slot: 6,
    position: [1.75, L.TBL_TOP + 0.52, -2.72], color: 0xffe08a, radius: 4.6,
    strength: () => astroApi.state.magicP,
    yMin: 3.02, yMax: 6.9,
  }),
],
```

`id` / `position` / `color` / `radius` / `yMin` / `yMax` 与搬走那一行**逐字相同**；
`strength` 由 `() => ctx.magicP` 改为读 **owner 的 state**（本件自己没有强度状态量）。
