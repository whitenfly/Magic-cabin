### 3.2 `astro`+`veil`+`star-particles` **与** `candle`（槽 5）—— **必须同批（4 件）**

**这是本阶段最需要提前知道的一条**（`J4.27` §6.2 查明、`J4.31` 复核）：

```js
// FrameBody 的每帧块是**交错**的：
frame/72  ctx.magicP += …            ← 18.5 星象仪的状态轴
frame/73  ctx.veil.material.opacity = ctx.magicP * 0.28;   ← 18.6 夜幕
frame/74  for (const cg of ctx.candleGlows) cg.m.material.opacity = … * ctx.candleP * boost * flick;
          //   ↑ boost = 0.30 + 0.50 * ctx.magicP  —— **蜡烛的辉光读了 veil 的状态**
frame/75+ spinG / innerG / glows / magicParts                ← 18.5 / 18.7
```

⇒ 把 `astro`+`veil`+`stars` 合并成一个 `update` 时，**必然把 `frame/74` 包进区间**，
而 `frame/74` 属于蜡烛 —— 反之单独搬蜡烛也会让 `magicP` 读到**上一帧的值**（画面必变）。

**前置状态**：✅ 光源槽 5 / 槽 6 的 `slot` 契约已由 `J4.18` 就绪；
⚠️ 还缺一个决策：**这 4 件是合成"一件"（`floor2/magic-veil` 作 owner）还是拆两件**

## 4. 已建立的**可复用模式**（后续任务照抄即可）

### 4.1 光源物件（含槽位）的搬法 —— 已被 `J4.22`–`J4.29` 验证 6 次

1. 删 `world/lights.js` 里那一行；
2. 在物件里写 `lights(s, { L }) => [createPointLightSource({ id, **slot: N**, position, color, radius, strength, yMin, yMax })]`
   —— **位置/颜色/半径/yMin/yMax 逐字照搬**；
3. 强度改为读**物件自己的 `state`**（`() => s.pt`，或 `(time) => s.pt * (…)` **逐字照搬**原表达式）；
4. 把 `tickOnce()` 里那行 `ctx.ptXxx += …` 平滑**并进物件的 `update`**（见 §4.2）；
5. 删 `WeatherSystem.js` 里对应的 `ctx.ptXxx = …` 初值（**一楼已全部清零**）。

### 4.2 一份物件只有一个 `update`：两段帧任务怎么合并

**判据（每次都这么做，可 grep 复核）**：
① 两段在原 `FrameBody.js` 里**相邻**（中间无别的帧任务）⇒ 合并后每帧序列不变；
② 若把靠后那段**提前**：它是**一阶低通**、同帧同 `dt` 同输入 ⇒ 逐位相同，
且 `grep <状态量>` 的全部命中只有本件（外加 `frame/97` 才被调用的 `lights()` 闭包）
⇒ **两位置之间无读者/写者**；
③ 合并后**仍须早于消费者**（`lightField.update` 在 `frame/97`）。

> 反例记录：`candle` 的 `frame/74` **读 `ctx.magicP`** 而 `magicP` 由 `frame/72` 更新
> ⇒ 把蜡烛合并到它自己的几何分支位置（`frame/35`）会让 `magicP` 读到上一帧的值 ⇒ **画面必变**。
> **这就是 §3.2"必须同批"的由来。**

### 4.3 段导出清单（**连续五次拦下故障**）

`world/floorN/install.js` 顶部有一批**段导出**，形如
`ctx.xxx = xxx;` —— 它们靠**函数声明提升**引用本段的局部函数/变量。
**只要被引用的东西搬走/提取走，该分句就会在装配期抛 `ReferenceError`**（页面起不来）。

⇒ **动作**：搬任何东西之前，先 `grep "ctx\.<名字>"` 确认**有没有读者**；无读者就删该分句，
有读者就改指向新家。

已拦下 5 次：`J4.20` `startQuill` · `J4.26` `makeCup` · `J4.28` `makeCushion` ·
`J4.30` `clockHand`/`drawClock` · `J4.31` `hash01`/`jitterGeo`。

### 4.4 共享件的抽取形态（`props/README.md` 已记账）

- **纯造型** ⇒ 无状态工厂（返回新 `Group`）；
- **跨摆放者共享的行为** ⇒ `createXxxFactory(deps)`，**集合住在闭包**（不违反 `N7`），
  且**必须在文件头写明理由**（先例：`props/cup.js`）。
- **共享数学/几何工具** ⇒ 直接 `export`，由 `propCtx` 注入（先例：`core/math/easing.js`、
  `core/geometry/jitter.js`）。
