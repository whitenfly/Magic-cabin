## 0. 一句话结论

**`J3` 留下的那处静默功能回归还清了**：全身镜的自建射线接回去，
「点击镜面泛起水波涟漪」这个入口回来了。

同时补上**这个缺口一直没有的那条判据** —— `pnpm test:mirror`：
对准镜面、发一次真实的 `pointerdown`+`pointerup`、看画面是否真的变，
并用一组"不点击"的对照把"推帧本身造成的变化"扣掉。

## 1. 为什么 C1 值得单列一个任务

它是 `J3`–`J4` 全程唯一**用户可感知**的回归，而且**三条门禁一起漏**：

| 门禁 | 为什么看不见它 |
|---|---|
| 像素回归 | 三机位是**固定视角的定格帧**，根本没人去点镜子；而镜面的高光与星星闪烁由 `dirtyT` 每 0.12 秒重绘驱动，**时序未变** ⇒ 画面逐字节相同 |
| 冒烟（32 项） | S4 点的是**壁炉**、S6 点的是**书堆**；S5.5 的第一人称点击打的是准星目标 |
| 交互探针 | 镜面**刻意**没有 `interactables`（见 §2.2），所以它不在 `aimMissing` 的判据范围内 |

> 与 [`J3.1`](J3.1-实施结果.md) §4 的盲区分析**同源**：
> **判据的粒度决定它能不能发现问题** —— "画面没变"不等于"功能还在"。

## 2. 做了什么

### 2.1 两处改动，射线**逐字**取自原始源文件

| 文件 | 改动 |
|---|---|
| `src/cabin/app/scene/PropInstaller.js` | 装配环境补两个键：`propTool('camera', …)` / `propTool('renderer', …)`（+5 行） |
| `src/cabin/world/floor2/mirror.js` | `build()` 的解构补 `camera, renderer`；`return` 之前接回**自建射线段**（+36 行，含注释） |

射线那 20 行取自**原始源文件** `line-art-style-magic-cabin-main/index.html` 的 `L6630–L6649`，
**逐字未改**（`J3` 搬本件时随几何区间一并删除）。唯一"新"的东西是它现在从装配环境取
`camera` / `renderer` —— 这正是路线图 C1 写的那条解锁条件（"给 `ctx` 补 `camera`/`renderer`"）。

### 2.2 为什么**不能**图省事改走主射线（这条约束必须写进代码）

`installProp` 的 ⑤.2 会把物件的 Mesh 加进 `magicMeshes`，从而获得准星/点击入口 ——
看似"一行都不用写"。但那条通路**要过家具遮挡判定** ⇒ 镜子一旦被家具挡住就点不到 ✗
而原实现是 `intersectObject(mirrorPane, false)` —— **只看镜子本身，不看遮挡**。

所以本件**不声明 `interactables`**（这是 `J3` 的判断，不是遗漏），探针的 26 件准星入口列表里
也没有它。射线段的注释里写明了这一点，避免将来有人"顺手统一"。

### 2.3 ★ 判据本身踩的坑：相机站在镜背面 ⇒ 永远落空，而画面完全正常

第一版判据把相机放在 `MZ + 2.2`（镜子的 +Z 侧）—— **测试失败，两次点击都是 0 像素变化**。
根因在 `mirror.js` 第 106 行：

```js
mirrorG.rotation.y = Math.PI;    // 镜面朝 -Z（贴前墙内侧、朝向屋内）
```

`PlaneGeometry` 是**单面**的，`Raycaster.intersectObject` 默认**只测正面** ⇒
从背面射过去必然打不到，**而画面看起来毫无异常**（镜子照样渲染、照样闪烁）。

> 这条值得单记：**判据失败的原因可能不在被测代码，而在判据自己站错了位置**。
> 处置不是"降低阈值让它变绿"，而是把相机挪到镜面正面（`MZ - 1.6`）。

## 3. 新增的常驻判据：`pnpm test:mirror`

`tests/e2e/mirror-ripple.mjs` —— 与冒烟、探针同级（它由 `J4.8` 建立，负责**不让射线再被删掉**）。

判据设计（**对照 + 实验**，把噪声扣掉）：

| 组 | 动作 | 期望 |
|---|---|---|
| **对照** | 对准镜面 → 截图 → 推 3 帧 → 截图 | 差异 ≈ 0（证明"推帧本身不改变画面"） |
| **实验** | 对准镜面 → 截图 → 派发真实 `pointerdown`+`pointerup` 到画面中心 → 推 3 帧 → 截图 | 差异**显著** > 对照（证明涟漪真的生成了） |

相机位与镜面坐标都**从 `layout.js` 取**（不变量 `N9`：坐标只有一个来源）——
注意 `FY` 是 `const FY = FLOOR_TOP`（**表达式**而非字面量），所以脚本直接 `import { createLayout }`，
不用正则抠数字（第一版抠字面量，当场抛"找不到 FY"）。

**实测**：

```
对照（不点击，推 3 帧）：差异像素 0
实验（点镜面，推 3 帧）：差异像素 117214   点击点 {"x":450,"y":300}
✓ 点击镜面后画面**显著**变化（涟漪真的生成了）
✓ 对照组本身几乎没有变化（说明差异来自点击，不是推帧）
✓ 全程无未捕获页面异常
```

## 8. 结论

`C1` 的交付面是 36 行射线 + 5 行装配环境，但真正补上的是**它一直没有的那条判据**。

这个缺口的可怕之处在于**三条门禁一起漏**：像素看不见（画面没变）、冒烟绕开（点的是别处）、
探针不在范围内（镜子刻意没有 `interactables`）。所以 `J4.8` 的产出不只是"把功能修回来"，
而是"让它在**下一次**被删掉时立刻报警" —— 这正是 [`J3.1`](J3.1-实施结果.md) 得出的那条：
**判据必须表达问题本身**（"点一下，看画面有没有真的变"），而不是问题的影子
（"代码里有没有那几行"）。
