## 1. 做了什么

把三段相机解算从 `updatePlayer()` 里搬进 `CameraRig`，并补上**运镜能力**：

| 能力 | 说明 |
|---|---|
| `defineMode(name, solver)` | 注册一种视角的解算方式（三视角由调用方注入，不是写死在 `core/`） |
| `update(state, dt)` | 每帧摆相机（在原 `updatePlayer()` 的位置调用） |
| `setMode(m)` | 切换视角（未注册的名字被拒绝，不静默切到空视角） |
| **`playScript({ duration, apply, easing, onDone })`** | **脚本化运镜**（`mode: 'scripted'`）—— `J6.5` 的"推移聚焦"与平面视角靠它 |
| `cancelScript()` | 中断运镜并**立即交还**（`BB8` 的"按 ESC 退出阅读"） |
| `applyShake(amount, runtimeRng)` | 相机抖动（位移部分；衰减与判据留在 monolith） |
| `applyTestCamera(cam)` | `J0.4` 的测试机位覆盖（只认"六个数"，不携带世界坐标） |

**三段解算逐字照搬**（`fixed` / `fp` / `tp`），`if / else if / else` 变成"按 mode 选 solver"。

## 2. 为什么视角状态不搬进 `core/`

`solver` 需要 `fixYaw` / `fixPitch` / `fixDist` / `camYaw` / `camPitch` / `viewDist`，
而这些是小屋自己的状态量。按不变量 `N1`（`core/**` 不得出现具体物件的变量名），
它们**留在 monolith**，每帧经 `state` 传进去：

```js
cameraRig.update({ fixYaw, fixPitch, fixDist, camYaw, camPitch, viewDist, player, look: FIX_LOOK })
cameraRig.defineMode('fixed', (s, cam) => { /* 用 s.fixPitch / s.look…，与原来一字不差 */ })
```

于是"搬迁期零差异"和"`core/` 不碰具体状态"同时成立。`viewMode` 与 `rig.mode` 在
`setViewMode()` 里保持同步（含 store 初始化那一次）。

## 3. ★ 验收 `BB16`：「3 视角下转场后均能正确交还」

`playScript()` 进入时记下 `modeBeforeScript`，结束时**自动把 `mode` 换回去**；
`cancelScript()` 同样交还（但不触发 `onDone`）。

`tests/unit/camera.test.mjs` 里有一条 ★ 测试**对三种视角各跑一遍**：

```js
for (const start of ['fixed', 'tp', 'fp']) {
  rig.setMode(start)
  rig.playScript({ duration: 1, apply: …, onDone: (restored) => done = restored })
  rig.update({}, 0.5)   // 脚本期间由 apply 接管
  rig.update({}, 0.5)   // 到点
  assert.equal(rig.mode, start)            // 交还给原视角
  assert.equal(done, start)                // onDone 收到交还后的视角名
  rig.update({}, 0)                        // 交还后由该视角的 solver 重新接管
  assert.deepEqual(calls, [start])
}
```

顺带锁住两条相关行为：
- **脚本期间 `setMode()` 不生效**（避免转场中途被切走）；
- **`cancelScript()` 也要交还**（中断不等于卡在脚本里）。

## 4. ⚠️ 给 `J6` 的一条硬约定（写在文件头注释里）

**平面视角（垂直俯视）的姿态不能用 `lookAt` 求**：视线 `(0,-1,0)` 与默认 `up=(0,1,0)` 平行，
叉积退化成零向量 ⇒ 矩阵坏掉**且不报错**。要直接由欧拉角构造
（`BuildPlaning/03` §3.4）。`CameraRig` 不做限制（`apply` 随便你怎么摆），
但这条写在文档与代码注释里，避免 `J6.5` 踩。

## 6. 实现中踩到的坑（判据如何追踪被搬走的随机调用）

把 `camShake` 的三行搬进 `CameraRig` 之后，`verify-migration` 立刻报
**`Math.random() 286 → 283`** —— 少的就是那三处随机调用。

原因：该判据按**名字**把 `runtimeRng()` 之类的调用反向还原成 `Math.random()` 再计数，
而搬进模块后形参名一度叫 `rng`，认不出来。两处调整（都记在 `CameraRig.js` 的注释里）：

1. 形参名改为 **`runtimeRng`** —— 它本就该是运行期随机源（不是构建期的场景种子），
   这个改动同时让判据能追踪到；
2. 注释里**不能出现带括号的裸随机字样**（第一次改完变成 `286 → 288`，多出来的两处
   就在注释里）。

> 这条经验对 `J3`/`J4` 同样有效：**搬迁 286 处随机调用时，形参名要保持可识别**，
> 否则计数判据会持续误报。

## 9. 一句话总结

**小屋第一次有了"运镜"这个能力**（风险 `R3` 消解）—— 三段解算逐字照搬所以画面未变，
而 `playScript()` + 自动交还（`BB16`）让 `J6` 的"走进书页"与平面俯视阅读有了着落；
视角状态仍留在小屋这边，`core/` 依旧不碰任何具体状态量。
