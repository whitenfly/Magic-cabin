> 编号 **`J4.4`** ｜ 分支 `task/J4.4-player` ｜ `--base=0.4.0` ｜ 上游：[`J4.3`](J4.3-实施结果.md)

## 0. 一句话结论

**一次搬四段**（碰撞 / 交互通路接线 / 输入 / 玩家控制）—— 玩家系统从 `legacy/monolith.js`
整体剪进 `systems/player/**` 与 `systems/interaction/Bridge.js`，代码逐字未改，
像素 **3/3 逐字节相同**、冒烟与探针全绿。

四段一次搬完是**刻意的**：它们互相引用（`playerCtrl` 用 `collision` 的 `collideXZ`/`groundAt`、
`input` 调 `playerCtrl` 的 `tryJump`/`setKnob`），分四次搬会让中间态"半截玩家系统"暴露在
门禁里 —— 而它们现在都走 `ctx`，一次搬完的验证强度并不下降。

| 段 | 原位置 | 现在住哪 | 行数 | 补 import |

四段在 `monolith.js` 里各只剩一行调用。

### 1.1 为什么 `sfxBridge` 住 `systems/interaction/` 而不是 `systems/player/`

它虽然叫"音效辅助"，但**主体是交互通路的接线**：

```js
const interaction = createInteractionSystem({ registry, warn })
interaction.registerProximity({ id: 'floor1/fireplace', … })   // 9 条近距条目
interaction.registerAimSource({ id: 'hinges',  meshes: ctx.hingeMeshes, resolve: … })
interaction.registerAimSource({ id: 'magic',   meshes: ctx.magicMeshes, resolve: … })
interaction.registerAimSource({ id: 'fire',    meshes: ctx.fireMeshes,  resolve: … })
function doInteract()      { … }
function updateInteractHint() { … }
```

`updateInteractHint()` 与 `doInteract()` 是**准星/近距两条通路的汇合点**，
下一阶段（`aim` 通路收进统一契约 = 路线图 `J4` 的 **C3**）要动的就是这里。

> 落在 `systems/interaction/` 还有一个即时好处：`registerAimSource({ id: 'magic', … })`
> 正是 **C3** 要删掉的那条独立通路 —— 它现在**住在一个独立文件里**，
> 合并 `installProp` ⑤.2 与 `magicMeshes` 时不必再在 6000 行里找它。

## 6. 结论

`J4.4` 把**玩家**这一整块（碰撞 / 输入 / 控制 / 交互通路）搬出了 monolith。

判据上有一处值得记：**像素回归对"玩家能不能动"几乎无感**（三机位都是固定视角的定格帧），
真正守住它的是**冒烟** —— S3 走位（移动 + 碰撞）、S5 切视角、S5.5 第一人称点击。
这与 `J3.1` 的教训同源：**判据的粒度决定它能不能发现问题**，
"画面没变"不等于"功能还在"。
