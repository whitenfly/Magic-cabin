## 1. ★ 四条帧任务：本阶段位移最大的一次合并

### 1.1 原样（`J4.37` §3.1 的帧序表）

| 原帧任务 | 原行 | 内容 |
|---|---|---|
| `frame/35` | L543 | `for (f of candleWavy) { f.obj.visible = true; updateWavyFlame(f, time, 0.9 + 0.1·sin(11t)) }`（**无条件**） |
| `frame/70` | L797 | `candleP += ((candleLit ? 1 : 0) − candleP) × 0.03` |
| `frame/71` | L798–799 | `candleVisible = candleP > 0.02`；`f.obj.visible = candleVisible`；**条件** `updateWavyFlame(f, time, candleP × (0.9 + 0.1·sin(9t)))` |
| `frame/74` | L808 | 三层辉光 `opacity` / `scale`，**`boost = 0.30 + 0.50 × magicP`** |

**分散程度**：`35` 与 `70` 之间隔着 **35 个别的帧任务**（猫 / 书架 / 水晶球 / 暖桌 / …）；
`70`/`71` 与 `74` 之间夹着 `astro` 的 `72` 与 `veil` 的 `73`。

> 对照：`magic-book`（`J4.36`）的两处 tick 只隔 **1 个**帧任务。

### 1.2 做法

合并成**一个** `update`，内部顺序 `35 → 70 → 71 → 74` **与原实现完全一致**，
登记在 **`astro` 之后**（`J4.37` §3.3 定的组 9 顺序 `astro → candle → veil → star-particles`）。

**新执行序**：

```
prop/astro(72,75,76) → prop/candle(35,70,71,74) → frame/73(veil) → frame/77(stars)
```

### 1.3 等价性（`J4.37` §3.4 判据 ②）

判据是「中间任务既不读也不写本件对象」。本件的依据是：

> **`candleWavy` 的全部读者已 grep 全仓 —— 只有 `FrameBody` L268（原 `frame/35`）与
> L544/L547（原 `frame/71`），两者都在本 `update` 内部，且内部顺序不变。**

⇒ 那 35 个"中间帧任务"与本件**无任何交互** ⇒ 合并等价，已由 `visual` **3/3 逐字节相同**实证。

## 2. ★ 跨件耦合：`frame/74` 读 `astro` 的 `magicP`

`boost = 0.30 + 0.50 × magicP` —— `magicP` 是组 9 的共享状态轴，owner 是 `astro`（`J4.38`）。
`astro` 的 `update` 排在本件**之前** ⇒ 读到的是**本帧**值（判据 ①）✓

### 2.1 ⚠️ 装配顺序陷阱（本件新踩到的坑）

`candle` 在 **18.3** 装配，`astro` 在 **18.5** —— **本件比 `astro` 早装配**，
所以装配那一刻 `ctx.astroApi` **还不存在**。

**而装配位置不能移**：它会决定 `candleG` 的 `scene.add` 次序，进而影响渲染顺序 ⇒ **画面会变**。

**处置：可变引用容器 + 回填**

```js
// 18.3（candle 装配之前）
const astroRef = { api: null };
ctx.candleApi = ctx.installProp(candle, { ctx: { astroRef } });
// …18.5…
const astroApi = ctx.installProp(astro);
ctx.astroApi = astroApi;
astroRef.api = astroApi;        // ★ 回填
```

本件的 `update` 每帧才读 `astroRef.api`，第一帧时两件都已装配完毕 ⇒ 安全。

> ⚠️ **不要用 `{ get astroApi() { return ctx.astroApi } }` 这种惰性 getter**：
> `install()` 会把 `ctx` 选项**合并**进 `propCtx`，合并那一步就可能立即求值 getter
> ⇒ 会拿到 `undefined` 并把它**固化**下来。

## 3. ★ 火焰材质：补进共享工具表（而不是复制色值）

原实现用 `ctx.fireMid` / `ctx.fireIn`（定义在 `world/house/shell.js` L244–245），
**与壁炉共用同一对材质实例**。它们原先**不在** `propCtx` 的工具表里。

`J4.34` §2.1 的先例（`D2R` 不在 `propCtx` 里）是「在模块里自造同值常量」——
但**那条处置会复制色值**：将来 `shell.js` 改火焰颜色时，本件不会跟着变。

⇒ 本件改为把**材质本身**补进 `propCtx` 的共享工具表（与 `makeWavyFlame` / `updateWavyFlame`
配套，见 `app/scene/PropInstaller.js`），**保持单一实例**。

**对照**：`floor1/cauldron.js`（`J4.29`）自造了三个材质 —— 但那是**另一套颜色**
（坩埚的蓝色魔法火 `0x3b6fd6`/`0x6fa8ff`/`0xcfe8ff`，与壁炉的 `0xb8421f`/`0xe0862e`/`0xf5c542`
不同），**并非重复常量**。两种情况不要混为一谈。

## 4. ★ 段导出清单：存量债**首次归零**

`install.js` 顶部那几行"段导出"里，原本挂着一批**局部工厂**。
每搬走一件，就得删掉对应项（否则留下指向已删函数的**悬空导出** —— 本项目已因此出错 **7 次**）。

|---|---|
| `J4.36`（magic-book） | `getGlyphTex` · `spawnGlyphs` · `updateGlyphs` · `updateBook`（4 项）|
| `J4.38`（astro） | `glowBall`（1 项）|
| **`J4.39`（本件）** | **`makeCandleGlow`（1 项）** |

⇒ **原有的 6 项已全部清空** —— 从此每搬一件只减不增。
（下方保留的 `addHalo` / `drawBoardFace` / `scrollRoll` / `woodPart` / … 属于**其它尚未搬迁的段**，
与已搬物件无关。）

## 5. 光源槽位 5

```js
lights: (s, { L }) => [
  createPointLightSource({
    id: 'floor2/candle', slot: 5,
    position: [L.NSX, L.FY + 1.00, L.NSZ], color: 0xffc06a, radius: 3.6,
    strength: () => s.candleP,
    yMin: 3.02, yMax: 6.9,
  }),
],
```

`id` / `position` / `color` / `radius` / `yMin` / `yMax` 与 `lights.js` 里搬走的那一行**逐字相同**；
`strength` 闭包由 `() => ctx.candleP` 改为读**物件自己的 state** `s.candleP`。

⇒ `lights.js` 现在**只剩 1 行**（槽 6 `floor2/magic-veil`），
等 `veil` 升格后该文件即**清空**（批 2 收尾）。
