## 0. 一句话结论

**全仓库最大的一段** —— 超位魔法系统（`monolith.js` L3806–L5107，**1301 行**、112 条语句、
79 个导出）—— 剪进 `src/cabin/systems/magic/MagicSystem.js`，代码逐字未改，
像素 **3/3 逐字节相同**，页面零错误。

这是 `J4` 单次搬迁的**最大交付面**：它一个人就顶得上 `J4.1`–`J4.4` 之和。

## 1. 做了什么

| | |
|---|---|
| 原位置 | `legacy/monolith.js` L3806–L5107 —— **1301 行** |
| 现在住哪 | `src/cabin/systems/magic/MagicSystem.js`（`export function installMagicSystem(ctx, app)`） |
| 段表 `bind` | `runtimeRng = runtime`（它住在 monolith 的模块顶层，不是 import、也不是 `app` 的解构） |
| 补的 import | **4 条** |
| 覆盖内容 | 魔杖模型 / 杖尖蓄力粒子 / 空中彩色魔力粒子 / 十字四芒星粒子 / 24 层魔法阵塔 / 网状光球 / 超级爆炸（16 种特效）/ 施法目标 / 一阶惯性跟随转向 / 施法压暗 / 爆裂魔法总调度 |

`--move` 的 `unknown` 判据**第一次就报出了 `runtimeRng`** —— 这正是它该干的事：
魔法系统里有大量运行期随机（碎屑飞散、火花、余烬），把它们悄悄丢给"未定义"会让页面直接起不来。

## 6. 结论

`J4.6` 把 `J4` 里**最大的单个系统**搬了出去，并且没有引入任何新的机制或判据 ——
`--move` + `--check` + 六项门禁这三步与 `J4.2` 搬 21 行的 audio 时**完全一样**。

这就是段切片的价值：**搬迁成本与代码量无关**。代价已经一次性付在 `J4.1`（ctx 化 + 三条修正）
上了。
