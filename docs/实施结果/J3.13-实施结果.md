## 1 · 现象与根因（★ 含一处**订正**）

### 现象

```
EPERM, Permission denied: \\?\D:\…\Magic-cabin\dist\posts
  at Object.rmdirSync          ← astro 的 emptyDir
  at AstroBuilder.build
```

后果：构建失败 ⇒ `task:done` 的门禁 `die` ⇒ **工具路径收尾被阻塞**。

### ★ 订正：我上一轮的判断有两处错

| 我上一轮说 | 实测结果 |
|---|---|
| 「**每次都会发生**（不是偶发）」 | ❌ **是偶发** —— `J3.13` 开头连续两次直接跑 `astro build` **都成功** |
| 根因是「astro 用已废弃的 `fs.rmdirSync`」 | ⚠️ **只是次要因素**。真正的主因见下 |

### 真正的根因（`J3.13` 实测）

**pnpm 子进程无法删除 `dist/`**：

| 执行方式 | 结果 |
|---|---|
| `node_modules\.bin\astro.CMD build`（直接跑） | ✅ **成功** |
| `pnpm.cmd build` | ❌ `EPERM`（**连 `fs.rmSync` + 5 次重试都失败**） |

⇒ 所以问题不在 astro 的 API，而在**经 pnpm 运行时子进程的删除权限**（沙箱差异）。
而 `task:done` 的门禁**恰恰走 pnpm**（`run('pnpm', ['build'])`）⇒ 必然踩中。

> astro 自身用**已废弃的** `fs.rmdirSync(recursive)`（Node 打 `DEP0147` 警告）让它更脆弱，但不是主因。
> **如实订正**：上一轮我把"偶发"说成了"每次必现"、把"次要因素"说成了"根因"。

## 2 · 修法（两条，缺一不可）

### ① 新增 `scripts/clean-dist.mjs` —— 用 `rmSync` + 重试**预先**清掉

```js
// ★ maxRetries/retryDelay：对 EBUSY / EPERM / ENOTEMPTY 等自动重试
rmSync(p, { recursive: true, force: true, maxRetries: 5, retryDelay: 120 });
```

清理发生在 astro 之前 ⇒ astro 的 `emptyDir` 面对一个**不存在**的目录，不再走那条脆弱路径。

### ② `runGates()` 改用**等价直调**（不再走 pnpm）

```js
function localBin(name) {
  const ext = process.platform === 'win32' ? '.CMD' : '';
  return join(ROOT, 'node_modules', '.bin', `${name}${ext}`);
}
function runBuild() {
  const c = run('node', ['scripts/clean-dist.mjs']);   // 先清理
  if (!c.ok) return c;
  return run(localBin('astro'), ['build']);            // 再构建（不走 pnpm）
}
// typecheck → localBin('tsc')；verify → node scripts/_verify.mjs
```

**这一步不违反规范**：§11 明确「`pnpm <别名>` 与直调**等价**」，§11.1 更已把"门禁调 pnpm 失败"列为
**降级路径**。门禁的**实质**仍是 typecheck / verify / build 三项，只是换了执行方式。

## 3 · ★ `package.json` 曾被改又被**回滚**（门禁发挥了作用）

我最初的方案是直接改 `package.json`：

```json
"build": "node scripts/clean-dist.mjs && astro build",
```

**`verify` 立刻把它拦下了**：

```
✗ scripts.build = astro build                        node scripts/clean-dist.mjs && astro build
✗ build:single 指向第二条产线                        node scripts/clean-dist.mjs dist-single && vite …
结果：56 项通过 / 2 项失败
```

`verify-j15.mjs` 有一条**硬断言**：`scripts.build` **必须等于 `astro build`**（不允许包装构建入口）。

**这条断言是有价值的**（保证构建入口唯一、CI 与本地一致），**不该绕过** ⇒ 我**回滚了 `package.json`**，
把清理只放在 `runGates()` 里（沙箱路径），**普通终端的 `pnpm build` 行为完全不变**。

> 📌 这是「**门禁是判据，不是装饰**」（红线 4）的正面案例：它挡住了一次"为了让工具好过而放宽构建入口"的改动。
