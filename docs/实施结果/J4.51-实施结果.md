## 1. 问题：跨层豁免 + 逐个列举

`J4.42` §2.4 裁决 `board` 编辑器归属时，`ctx.noteInput` 有两个**系统层**读者
（`Input.js` L24 · `PlayerController.js` L20，作用都是"在输入框里打字时吞掉游戏快捷键"），
当时取了方案 (a)：由 `board.js` 经 `parts.noteInput` 交出去、`install.js` 写回 `ctx.noteInput`。

那是一处**显式、带注释**的跨层豁免（`world/**` → `systems/**` 的实现依赖），能工作，但有两个毛病：

1. **每加一个输入框都要记得回来补一句** —— 漏了就是"打字时人还在走"；
2. 系统层必须**认识具体输入框**，而其中一个是**物件层**的东西 ⇒ 才需要豁免。

## 2. 改动与那次**有意的行为变更**

```js
// Input.js —— 统一判据（挂到 ctx 供两处共用；Input 段在 PlayerController 之前执行）
function isTypingTarget() {
    const el = document.activeElement;
    if (!el) return false;
    return el.tagName === 'INPUT' || el.tagName === 'TEXTAREA' || el.isContentEditable === true;
}
ctx.isTypingTarget = isTypingTarget;
```

两处读者改为：`if (isTypingTarget()) return;` / `const typing = ctx.isTypingTarget();`

| | 原来（列举式） | 现在（统一判据） |
|---|---|---|
| 那 3 个文本框（路牌 / 便签 / 画像） | 吞按键 | 吞按键（**不变**） |
| ★ **设置面板的 `<input type="range">` 滑块** | **不吞** | **吞** ← **行为变更** |
| 其它任何新输入框 | 不吞 | 吞 |

**滑块那条要说清楚**：它拖完**不会 blur**（`SettingsForm.js` 只把 `dragging` 清掉）
⇒ **拖过一次音量 / 时间流速滑块后，若不去点别处，键盘就走不动路了**。

这不是 bug，是"统一判据"的必然结果 —— 本任务把它**写成断言**（`pnpm test:input` 的
"自造 range input" 场景），让它成为**被记录的决定**，而不是悄悄发生的事故。
若要消掉这个不便，正确做法是**让滑块拖完主动 blur**（属设置面板的交互设计，不在本任务范围）。

## 3. 判据：`pnpm test:input`（`tests/e2e/input-guard.mjs`）

每个场景：把焦点放到指定元素 → **先断言焦点真的到位** → 按一次 `KeyW` + 推 40 帧 → 读**玩家位移**。

| 场景 | 期望 | 改前实测 | 改后实测 |
|---|---|---|---|
| 不聚焦任何元素 | 玩家**明显移动**（对照组） | ✅ 0.704 m | ✅ 0.704 m |
| 聚焦**自造的** text input | 不动 | ❌ **0.434 m**（列举式不认识它） | ✅ **0.000 m** |
| ★ 聚焦**自造的** range input | 不动 | ❌ **0.466 m** | ✅ **0.000 m** |

**TDD 顺序**：先写判据 ⇒ 跑出红 ⇒ 改代码 ⇒ 转绿 ⇒ 负例（把 `isTypingTarget` 退回列举式）⇒ **再红**
（0.434 / 0.466 m，`exit 1`）⇒ 恢复 ⇒ 再绿。

★ **为什么"自造 input"而不是页面里现成的输入框**：现成的 `#signInput` 在**默认隐藏**的弹出容器里，
而**隐藏元素无法获得焦点**（见 §4 坑 1）；自造的 input 一定可见、且**天然不在**原列举名单里，
正好是"统一判据 vs 列举式"的分水岭。原有 3 个文本框不回归这件事，由
"`tagName === 'INPUT'` 全覆盖 `<input type="text">`"在逻辑上保证。

## 4. 判据自身踩的两个坑（都写进了代码注释）

1. **隐藏元素无法获得焦点** —— `#signInput` 在 `display:none` 的容器里，直接 `focus()` **静默失败**
   （`activeElement` 仍是 `BODY`）⇒ 第一版判据测的其实是"没聚焦"，两个场景**假红**。
   ⇒ 现在每个场景都**先断言焦点到位**（`前提：焦点已在 … 上`），并改用自造 input。
2. **相机不能代替玩家位置** —— `viewMode === 'fixed'` 下相机固定在屋外，玩家在屋里走动时它**一动不动**
   ⇒ 位移必须读 `window.__cabinPlayer()`（`J4.51` 新增的探针，玩家不是 `defineProp` 物件，
   `__cabinPropState` 读不到它）。

## 6. 遗留

1. **滑块拖完不 blur** ⇒ 统一判据下"拖过滑块后键盘走不动"。这是**有意的行为变更**，
   已在 §2 写明；若要改，属设置面板的交互设计（让滑块 `pointerup` 时 `blur()`）。
2. **`contentEditable` 从未被实测** —— 判据只覆盖了 `INPUT`（text / range）。
   当前项目没有 `contentEditable` 元素，所以它只是"顺手写进去的完整语义"。
3. **`ctx.signInput` / `ctx.picInput` 仍挂在 ctx 上**（`MenuPanel.js` / `picture.js` 自己还要用），
   它们不再是"输入判据"的依据，但**没有删** —— 删它属清理，与本任务的收敛目标无关。
