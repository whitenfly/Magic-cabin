## 与 `world/**` 的分工

| | `cabin/world/**` | `cabin/props/**`（本目录） |
|---|---|---|
| 职责 | **摆放**：位置、朝向、所属楼层、挂载点 | **造型**：几何与材质工厂 |
| 状态 | 场景实例的状态（开/关、抽出/推回） | **无状态** —— 工厂函数，返回新的 `Group` |
| 被谁用 | 场景装配 | `world/**` 的 `build()` 里调用 |

```js
// props/teapot.js —— 无状态工厂
export function makeTeapot({ color = 0x8d6e63 } = {}) { /* … 返回 THREE.Group … */ }

// world/floor1/longTable.js —— 摆放者
import { makeTeapot } from '@/cabin/props/teapot'
put(makeTeapot(), 0.3, top, -0.1, 0, 0, 0, tableG)
```

## 两条约束

> ### ⚠️ 约束 1 的例外：**跨摆放者共享的行为**（`J4.26` 实装 `cup.js` 时记账）
>
> 当一件道具的**行为**要被**多个摆放者共享**时，行为可以随工厂一起提供 ——
> 否则"每帧动画遍历哪个集合"无处安放。首个反例是**茶杯**：
>
> - 造型（杯身 / 把手 / 三缕水汽）要用两次以上 —— 长餐桌 3 只 + **12.13 暖桌** 2 只；
> - 每帧的"升腾 / 冒汽"要遍历**同一个** `cups` 集合 —— 暖桌那 2 只必须在内；
> - 每只杯子还有**自己的一条交互**（点一下升腾 2.6 秒）。
>
> 按纯造型工厂拆，`cups` 集合与每帧遍历就**无处安放**（再造一个"共享行为模块"
> 只是把问题挪了个地方）；而让暖桌去 import 长餐桌模块的内部数组，
> 正是 `J3` 判「暖桌搬不动」的那条耦合
> （见 `scripts/oneoff/_j3-specs/floor1-kotatsu.SKIP.md` 的「阻塞二」）。
>
> ⇒ 采用形态 **`createXxxFactory(deps)`**：造型 + 每帧行为 + 每只道具自己的交互都在里面，
> **集合住在闭包里**（不是模块级单例 ⇒ 不违反不变量 `N7`），
> 摆放仍由各物件自己声明（谁放几只、放在哪，写在各自的装配点里）。
>
> **这不是放宽约定，而是把"共享行为"这一类显式登记下来**：后续遇到同形的道具
> （上表里的"沙漏 / 纸品 / 书"都可能跨处出现）可照此办理，
> 但**必须在文件头写明理由**（先例：`props/cup.js` 的「为什么是工厂而不是模块级单例」）。
>
> ⚠️ 这条**只适用于"真的被两个以上摆放者共享"的道具** —— 约束 2 仍然照旧。

1. **`props/` 不注册交互、不注册光源** —— 那是摆放者（`world/**` 的 `defineProp`）的职责。
   工厂只负责"长什么样"。
2. **搬进本目录的唯一理由是"真的重复"**（≥2 处）。
   只出现一次的道具留在自己的 `world/**` 文件里，不要为了"看起来整齐"而抽出来 ——
   那会让单件搬迁变成跨文件改动，破坏"一个物件一次提交"的规矩。
